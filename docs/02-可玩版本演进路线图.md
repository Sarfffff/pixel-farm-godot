# 可玩版本演进路线图（每版游戏长什么样）

配套文档：`01-游戏开发全流程.md` 讲"每个阶段该做什么事"，本文讲"每个版本做出来是什么样、能玩到什么程度"，具体技术方案对照见 `03-参考项目技术对照.md`。

**核心原则：地图先行。** 地图不是美术背景，它是坐标基准：相机范围、碰撞边界、交互单元（哪一格）、存档单元（哪块地种了什么）全部以它为基础。地图先立住，后面的行走、耕地、种植、动物、存档都是往同一套格子上叠，改一次不会推翻全局。

---

## 版本总览

| 版本 | 一句话 | 屏幕上出现什么 | 玩家能做什么 | 对应阶段 | 预估 |
| --- | --- | --- | --- | --- | --- |
| V0.1 | 静态农场地图 | 一片草地农场，有木屋、池塘、农田区、树和栅栏 | 只能看（无操作） | 2–3 | 1–2 天 |
| V0.2 | 能走路 | 同上 + 一个小人（猫）站在屋前 | 四向移动，镜头跟随 | 3 | 1 天 |
| V0.3 | 能逛完整农场 | 农场全部完成：小溪、木桥、小路、Y 轴遮挡、边界碰撞 | 走到任意可达处，被水和栅栏挡住 | 3 | 2–3 天 |
| V0.4 | 能改地形 | 手持锄头/水壶图标，面前地块出现白色高亮框 | 切换工具，锄出耕地、浇水变深色 | 3 | 2–3 天 |
| V0.5 | 能种地 | 耕地里出现小苗，随时间长大 | 选种子播种，作物按阶段生长 | 3 | 2–3 天 |
| V0.6 | 能赚钱 | 金币数、背包格、商店面板 | 收获进背包，卖货得钱，买新种子 | 3–4 | 3–4 天 |
| V0.7 | 能长期玩 | 时钟和天数、睡觉结算画面 | 睡觉进入下一天、随时存档读档 | 4 | 3–4 天 |
| V0.8 | 有第二条产出线 | 鸡舍前有鸡走动，地上有蛋 | 捡蛋、卖蛋 | 4–6 | 3–4 天 |
| V0.9 | 能交给别人玩 | 引导提示、帮助界面、设置菜单 | 陌生人不问人也能玩完第一天 | 4–8 | 4–6 天 |
| V1.0 | 能发布 | 完整音效反馈、正式 UI、无占位资源 | 完整 7 天体验闭环 | 6–9 | 1–2 周 |

> V0.4 结束就"能走能改地"，V0.6 结束就有了**第一个真实可玩循环**，V0.7 结束才叫"农场游戏"。前 6 个版本都在验证，不要往里塞内容。

## 全局画面基准（V0.1 就定死，后面不改）

| 项 | 值 | 理由 |
| --- | --- | --- |
| 瓦片尺寸 | 16×16 px | 现有素材全部按此网格 |
| 基准视口 | 320×180 px（显示 20×11.25 格） | 1280×720 恰好 4 倍、1920×1080 恰好 6 倍，整数缩放不糊 |
| 窗口 | 1280×720，可拉伸 | `canvas_items` + `expand` 已配置 |
| 贴图过滤 | Nearest（`rendering/textures/canvas_textures/default_texture_filter = 0`） | 当前未设置，默认线性会让像素发糊，**必须改** |
| 农场地图 | 40×30 格（640×480 px），相机跟随 | 略大于一屏，有探索感又不至于空 |
| 对齐 | 所有精灵坐标取整，锚点用"脚底中心" | 防止抖动与遮挡错位 |
| 排序 | 物件层用 `y_sort_enabled`，以脚底 y 比较 | 走到树后/屋后正确遮挡 |

## V0.1 静态农场地图

**一句话**：打开游戏，看到一片完整但静止的农场。

### 画面

- 整个可见区域是草地，边缘是树、灌木、石头，右侧一栋木屋（屋顶、墙、门三件套拼好），左中一大块翻好的耕地，右下角一汪会微微流动的池塘。
- 没有 UI、没有角色、没有文字，纯地图。
- 相机固定在地图中央，只能看到地图中部，边缘看不到（用于确认相机裁剪正常）。

### 玩家能做什么

无操作。这一版的交付物是"一张能跑的地图"，不是"一个游戏"。

### 新增资源与文件

| 类型 | 路径 | 说明 |
| --- | --- | --- |
| TileSet | `assets/tilesets/farm_terrain.tres` | 建草地、耕地、水、道路四套地形，按 16×16 切格 |
| 地形场景 | `scenes/world/terrain.tscn` | 用 `TileMapLayer` 分层：地面层、装饰层、物件层 |
| 农场场景 | `scenes/world/farm.tscn` | 组合地形 + 木屋 + 树 + 栅栏，设为 `main.tscn` 的子场景 |
| 脚本 | `scripts/world/farm.gd` | 目前只负责初始化与调试输出 |

### 验收标准（对照截图即可判定）

- [ ] 16×16 网格对齐，无半像素缝隙、无缝隙黑边
- [ ] 草地与耕地、水与陆地交界处过渡自然，没有突兀直角
- [ ] 池塘水面有 4 帧循环动画（当前为静态水，动画排在 V1.0 打磨）
- [ ] 木屋可辨认、门朝向可读
- [ ] 画面无模糊（像素边缘锐利），无拉伸变形
- [ ] 控制台无 `SCRIPT ERROR` / `ERROR`

### 明确不做

角色、碰撞、交互、UI、音效、存档、任何会动的东西（水动画除外）。

### 实际记录（2026-11-02，已完成）

**已交付**

| 内容 | 实现 |
| --- | --- |
| 像素基准 | 视口 320×180、窗口 1280×720、贴图过滤 Nearest，画面 4× 整数缩放无模糊 |
| 地形资源 | `assets/tilesets/farm_terrain.tres`：草地（27 个瓦片，含 3×3 圆角地块、12 个地面变体、6 个装饰）、耕地（15 个瓦片）、水面 |
| 地图场景 | `scenes/world/farm.tscn`：`Ground` / `Water` / `Overlay` / `Detail` 四层 `TileMapLayer` + `Props`（已开 Y 排序） |
| 地图规格 | 40×30 格（640×480 px），4 块 4×3 苗圃、10×7 池塘（草岸）、36 个道具实例 |
| 道具场景 | `scenes/world/props/`：cottage、tree_big、tree_small、tree_fruit、bush、rock、mushroom、log_pile |
| 入口场景 | `scenes/main.tscn`：`Camera2D`（位置 392,152）+ farm 实例 |
| 地图生成器 | `tools/build/build_farm_map.gd`：固定随机种子，一条命令重建整张地图，含瓦片声明预检 |

**与计划的差异（已确认可接受）**

1. **木屋改为现成整栋小屋**：`wooden_house.png` 是墙体/屋顶/门的构件图，直接拼装风险高；先使用 `free_chicken_house.png`（48×48 完整小屋）作为农舍占位，真正的木屋拼装留到 V0.8 与鸡舍一起做。
2. **农田改为 4 块苗圃**：整块 10×8 耕地是一片纯色（素材本身无纹理），视觉上像一块空地；拆成 4 块 4×3 圆角苗圃 + 1 格草地通道后更有"农庄"感，也更贴合 V0.4 逐格锄地的交互。
3. **水面静态**：暂不做 4 帧动画，原因是 `TileSetAtlasSource` 的动画帧序列化格式需要先验证；静态水不影响 V0.2–V0.8。
4. **暂不做栅栏与小路**：`fences.png` 与 `paths.png` 的拼法需要逐个瓦片验证，放进 V0.3（完整布局 + 碰撞）一起做，避免这一版引入半成品。

**重建方式**

```powershell
& 'E:\Godot_v4.7.2-stable_win64.exe' --headless --path e:/my-ai-game --script res://tools/build/build_farm_map.gd
```

改布局只需改脚本里的 `PLOTS`（苗圃）、`POND`（池塘）、`PROP_TABLE`（道具坐标），再跑一次即可；瓦片声明漏了会在运行时报错并中止，不会静默画出空洞。

## V0.2 玩家与镜头

**一句话**：小人从屋前出发，能用方向键在草地上走动，镜头跟着他。

### 画面

- 地图中央出现一个 16×16 的猫角色，起始站在屋门前。
- 走路时播放四向行走动画（下/上/左/右各一组），停下回到对应朝向的站立帧。
- 镜头平滑跟随，角色始终大致居中；地图边界处镜头停住不越过。

### 玩家能做什么

- `WASD` / 方向键 四向移动，斜向移动速度不叠加
- 角色与树的"脚底"重叠时，树挡住角色（先验证一次遮挡即可，完整遮挡在 V0.3）

### 新增资源与文件

| 类型 | 路径 | 说明 |
| --- | --- | --- |
| 玩家场景 | `scenes/player/player.tscn` | `CharacterBody2D` + `AnimatedSprite2D`（脚底锚点）+ 碰撞体 |
| 玩家脚本 | `scripts/player/player.gd` | 移动、朝向、动画状态切换（替换现有占位脚本） |
| 帧资源 | `scenes/player/player_frames.tres` | 从 `basic_charakter_spritesheet.png` 按 16×16 切帧 |
| 输入映射 | `project.godot` → `Input` | `move_up/down/left/right` |

### 验收标准

- [ ] 八向移动顺滑，无卡顿、无斜向加速
- [ ] 四向动画与移动方向一致，切换无闪烁、无错帧
- [ ] 碰撞体比视觉体积小（能贴着树走，不会隔空被挡）
- [ ] 镜头跟随有轻微缓动，走到地图边缘时镜头停住
- [ ] 连续跑 5 分钟无报错、无位置漂移

### 明确不做

交互、工具、耕地、UI、碰撞层细节（V0.3 补）。

### 实际记录（2026-11-02，已完成）

**已交付**

| 内容 | 实现 |
| --- | --- |
| 输入映射 | `project.godot`：`move_up/down/left/right`，每个动作绑 W/A/S/D + 方向键，deadzone 0.2 |
| 玩家场景 | `scenes/player/player.tscn`：`CharacterBody2D`（`MOTION_MODE_FLOATING`）+ `AnimatedSprite2D`（原点在脚底）+ 半径 5 的圆形碰撞（下移 4px 贴脚） |
| 玩家脚本 | `scripts/player/player.gd`：72 px/s 走速、900/1100 加减速、四向朝向记忆、斜向按主轴取朝向 |
| 帧资源 | `scenes/player/player_frames.tres`：8 个动画（`idle_*` 单帧 / `walk_*` 4 帧 8fps），由 `tools/build/build_player_frames.gd` 生成 |
| 相机 | `scripts/presentation/camera_follow.gd`：平滑跟随（speed 8）+ `limit_*` 限制在 640×480 地图内，`focus_offset` 上移 10px |
| 生成器 | `tools/build/build_player_frames.gd`、`tools/check/smoke_check.gd`（无窗口自检：输入映射/动画/玩家场景/主场景） |

**图集实测（重要，供后续复用）**

`basic_charakter_spritesheet.png` 并非紧贴排布的图集：帧尺寸 16×16，首个帧左上角在 (16,16)，**帧间隔 48px**，共 4 行 4 帧。
行顺序为 **下 / 上 / 左 / 右**，第 4 行是第 3 行的水平镜像（256/256 像素一致），已通过像素比对确认。

**与计划的差异（已确认可接受）**

1. **提前加入地图边界墙**：原计划碰撞留到 V0.3，但无边界时角色会走出地图、相机卡在边缘导致角色消失。现由生成器在 `farm.tscn` 写入 `Bounds`（`StaticBody2D` + 4 面 32px 厚墙），只做外围围挡，建筑与水体碰撞仍属 V0.3。
2. **碰撞体为圆形**：半径 5 贴脚部，比 14×16 的视觉体积小，符合"能贴着树走"的目标；V0.3 若出现卡角再改胶囊或矩形。
3. **镜头无死区**：暂用全局平滑跟随，死区与前瞻（look-ahead）留到 V0.8 手感调优再加。

**验证结果**

- `tools/check/smoke_check.gd` 通过（输入映射 8 个按键、8 个动画帧数、玩家与主场景节点完整）
- 实机模拟按键：上/下/左/右均切换到对应 `walk_*` 动画，朝向与图集一致
- 边界墙生效：角色停在 x≈5、y≈9，无法穿出地图
- 控制台无 `SCRIPT ERROR` / `ERROR`

## V0.3 能逛完整农场

**一句话**：农场完全成型，玩家能走到每个可达区域，被水、栅栏、树木正确挡住。

### 画面

- 相比 V0.2 新增：南侧小溪与木桥、贯穿屋门到农田的小路、东/南栅栏、北西边缘的树与灌木、石头。
- 角色走到树后会被树冠遮住上半身，走到屋后会完全被房子挡住。
- 池塘边、小溪边有明确岸线，踩不进去。

### 玩家能做什么

- 在可达区域自由行走（草地、小路、木桥、农田空地）
- 无法穿过：池塘、小溪（除桥）、栅栏、树、木屋墙体
- 过桥时相机跟随，能完整看到南北两侧

### 新增资源与文件

| 类型 | 路径 | 说明 |
| --- | --- | --- |
| 地形补充 | `farm_terrain.tres` 增加"水岸""道路"地形集合 | 小溪与池塘共用 |
| 物体场景 | `scenes/world/props/*.tscn` | 木屋、树、灌木、石头、桥、栅栏各自一个可复用场景 |
| 碰撞 | 各物体内置 `CollisionShape2D`，图层区分"实体/可交互/装饰" | 便于后续交互查询 |
| Y 排序 | 物件层开启 `y_sort_enabled`，精灵设 `y_sort_origin` | 正确遮挡 |

### 验收标准

- [ ] 沿地图边缘走一圈，没有能被挤出去的位置
- [ ] 所有水体、栅栏、建筑都不可穿越，桥面可通行
- [ ] 遮挡正确：从下往上走时角色被树/屋遮挡，从上往下走时角色在物件前面
- [ ] 画面无"卡角"（沿墙体移动时不会抖动或卡死）
- [ ] 地图完整截图可作为阶段 3 的美术基准

### 明确不做

任何交互、任何会变的地形、UI。

### 实际记录（2026-11-02，已完成）

**已交付**

| 内容 | 实现 |
| --- | --- |
| 场景结构重构 | `farm.tscn` 由生成器从零构建：`Ground` / `Water` / `Overlay` / `Detail` / `WaterCollision` / `World`(y_sort) / `Bounds` |
| Y 轴遮挡 | `World` 开启 `y_sort_enabled`，`Player` 移入 `Farm/World`，与全部道具同一个排序容器 |
| 道具碰撞 | 小屋、大树、小树、果树、灌木、石头、木堆各加 `StaticBody2D`（树干用圆形、其余用底部矩形）；蘑菇保持可穿过 |
| 水体碰撞 | TileSet 增加 `physics_layer_0`，水面瓦片带 16×16 多边形；碰撞只铺在池塘内圈，岸线一格仍可站立（视觉上是浅滩） |
| 边界墙 | `Bounds` 4 面 32px 厚静态墙，角色无法离开地图 |
| 自检 | `tools/check/smoke_check.gd` 扩展为 6 组检查（输入/动画/玩家/农场结构/道具碰撞/主场景） |

**验证结果**

- 遮挡：角色走到树下（y 小于树脚）时被树冠覆盖，只剩耳朵从树冠上沿露出
- 道具碰撞：从树上方往下走，角色停在 y≈62（树干圆心 68、半径 5 + 角色半径 5 + 碰撞点上移 4，与计算一致）
- 水体碰撞：从池塘北岸往下走，角色停在 y≈315（内圈上沿 320 − 半径 5），站在岸边浅滩
- `smoke_check` 全绿，实机运行控制台无 `SCRIPT ERROR` / `ERROR`

**与计划的差异**

1. **小路放弃**：`paths.png` 的木板瓦片不是无缝拼接设计，实测铺成路面后呈"散落木板"，已移除，并把新增的 TileSet source 一并删掉，避免留下无效配置。农场主路留到有合适贴图时再做。
2. **栅栏未做**：`fences.png` 的柱/栏组合需要逐瓦片验证连接方式，本版优先保证碰撞与遮挡正确，栅栏留到 V0.8（与鸡舍围栏一起做）。
3. **小溪/木桥未做**：地图南侧暂为开阔草地，木桥与溪流作为 V0.8 的"通往镇子"出口一起规划。
4. **池塘碰撞取内圈**：用 `WaterCollision`（z=-1，被草地遮住）单独负责碰撞，视觉水面层不参与碰撞，这样岸线瓦片不会被"误判成水"而挡住玩家。

### 遮挡淡出（2026-11-02 追加）

**问题**：Y 排序只保证"谁在前谁在后"，角色走到树冠或屋顶后面时会被完整遮住，玩家看不到自己。

**方案**：`scripts/presentation/occlusion_fader.gd` 挂在 `World` 上，每物理帧检查每个道具，**同时满足**两个条件才淡出：

1. 道具脚底 y > 角色脚底 y（道具被排在前面，会盖住角色）；
2. 角色的**脚底点**落在道具遮挡框内（遮挡框左右各内缩 4px）。

> 判定规则改过一次：最初用"贴图包围盒相交"，结果角色只是站在房子**侧面**、身体蹭到墙面也会淡出。改成脚底点 + 水平内缩后，只有角色真正站进道具脚下/身后才命中，侧面经过不再误判。

命中时用 `Tween` 把 `modulate:a` 补到 0.55（0.12s），离开后补回 1.0。包围盒在 `_ready` 缓存一次（道具不移动），只在目标透明度变化时重建 Tween。

**同时修正**：小屋碰撞体原先只覆盖底部 40×14，角色能从侧面走进房屋内部；已改为 40×40（覆盖建筑轮廓），角色只能站在门外、不能穿进屋里。

**验证**：站在小屋背后 → 小屋降到 55% 透明度，角色可见；站在树后 → 树冠变半透明，角色可见；站在道具**侧面** → 保持 100% 不透明；走到道具前方 → 透明度恢复 100%。`smoke_check` 增加"World 必须挂载 occlusion_fader"的回归检查。

### 贴图取区修正（2026-11-02 追加）

**问题**：地图上出现"侧翻的树"（绿色树冠连着棕色树桩横躺在地上）。

**原因**：`basic_grass_biom_things.png` 的第 4 行第 0–1 列是**倒下的树**，与第 2 行第 5 列的原木很像，取区时选中了前者。

**修正**：`log_pile.tscn`（区域 `(36,64,32,16)` = 倒树）删除，新建 `scenes/world/props/log.tscn` 使用真正的原木 `region_rect = Rect2(80, 32, 16, 16)`，`offset.y = -5` 让原木底边贴地，碰撞 14×8。

### 碰撞体取法规则（2026-11-02 追加）

碰撞体按"**落地轮廓**"取，而不是按贴图大小：

| 类型 | 取法 | 例子 | 原因 |
| --- | --- | --- | --- |
| **建筑** | 只覆盖**墙体和台阶**（落地部分） | 小屋 `40×24` @ `(0,-12)`，贴图 48×48 | 屋顶属于"空中"，其屏幕位置对应的是房子背后的地面；如果按整张贴图挡，会在地图北侧形成一圈看不见的墙，角色被推得离房子很远 |
| **矮物件** | 只覆盖**底部落地部分** | 树用半径 4–5 的圆、灌木/石头/原木用底部矩形 | 树干很细，树冠悬空；只挡树根才能贴着树走 |

屋顶怎么办：角色走到房子背后时会进入屋顶的屏幕范围，此时由 `occlusion_fader` 把房子淡到 55%，角色隔着半透明屋顶可见——这就是"走到房子后面"的标准表现。

小屋碰撞体演进：`40×14`（会穿墙进屋）→ `40×40`（挡住 2.5 格，离房子太远）→ `44×48`（与贴图等高，北侧出现无形墙，角色被顶到屋顶上方）→ **`40×24`（只挡落地墙体，角色能正常贴到房子背后）**。

| 道具 | region_rect | 说明 |
| --- | --- | --- |
| `tree_small` | `(0, 0, 16, 32)` | 细高树 |
| `tree_big` | `(16, 0, 32, 32)` | 圆冠大树 |
| `tree_fruit` | `(48, 0, 32, 32)` | 心形果实树 |
| `bush` | `(0, 48, 32, 16)` | 一丛两个灌木（带花 + 素） |
| `log` | `(80, 32, 16, 16)` | 原木（**不要用 (36,64)，那是倒下的树**） |
| `rock` | `(112, 16, 32, 16)` | 大小两块灰石 |
| `mushroom` | `(112, 0, 32, 16)` | 两朵紫色蘑菇 |

### 实际记录（2026-11-02，已完成）

**已交付**

| 内容 | 实现 |
| --- | --- |
| 输入映射 | `use_tool`(Space)、`mouse_use`(鼠标左键)、`tool_prev`(Q)、`tool_next`(E)、`tool_1/2/3`(1/2/3) |

| 可开垦范围 | `Rect2i(16, 5, 14, 10)`，覆盖 4 块苗圃并允许向四周扩 1 格 |

**设计决定**

1. **每格独立方块，不做自动连边**：第一版按九宫格邻接拼合，单格凸起会渲染成"城垛"（见开发过程截图），而素材里并没有"单格独立地块"图。改为每格统一铺地格后，锄出来永远是规整矩形，行为可预测。代价是失去圆角美观，等有独立地块素材再换。
2. **地块绘制权收归 Tiller**：原先苗圃由生成器画在 `Overlay` 层，玩家新锄的地却在 `Soil` 层，两处逻辑容易分叉。现在统一由 Tiller 画在 `Soil`/`Watered` 层。
3. **湿土用调制而非新贴图**：现有素材没有"湿土"图，用同款瓦片叠一层压暗的 `Watered` 层实现，效果可读且零美术成本。
4. **铺地格用坐标哈希挑碎石变体**：`(x*73856093) ^ (y*19349663)`，保证同一格每次重画结果一致，不会闪烁。

**与计划的差异**

1. **工具挥动动画未做**：`basic_charakter_actions.png`（96×576，6×36 格）的具体分帧规则还没验证，先不做；锄地/浇水目前只有地块变化反馈。留到 V0.9 统一做动作与音效。
2. **种子袋槽位为占位**：`seeds` 工具已进入工具栏但使用无效（V0.5 接播种）。
3. **未做"无效操作反馈"**：目前无效格只是隐藏高亮框，没有音效或提示文字，等 V0.9 的反馈层统一补。

**验证**

- 实机：鼠标左键锄地生成规整方块耕地、数字键切换工具、切到水壶点左键浇水后变深、高亮框随朝向移动、锄完该格后高亮消失（不可再锄）、工具栏高亮跟随切换
- `smoke_check` 增加耕地相关断言（Soil/Watered 层、Tiller 脚本、Cursor 子节点、`mouse_use` 等动作存在性）PASS
- 控制台无 `SCRIPT ERROR` / `ERROR`

### 观感与 UI 调整（2026-11-02 追加）

**1. 耕地太突兀**

素材的耕地底色 `(232,207,166)` 明显亮于草地，一整块铺上去像贴纸。处理：

- `Soil` 层 `modulate = (0.88, 0.82, 0.72)`，把亮度压到接近草地的明度区间
- `Watered` 层同步改为 `(0.70, 0.62, 0.54)`，保持"湿土更暗"的层级关系
- 碎石细节变体比例从 30% 提到 50%，地块不再是一大片纯色

**2. 工具栏不像像素游戏**

原来用 `PanelContainer` 默认主题（深灰圆角 + 粗体无衬线字母），和 16px 像素画完全不是一套语言。改为：

- 槽位用 `StyleBoxFlat` 手写：不透明深色底 + 1px 米色描边 + 直角，接近像素 UI 的观感
- 图标改用素材自带的 `assets/textures/base/characters/tools.png`（16×16）：锄头 `(0,4)`、水壶 `(0,0)`、种子袋 `(3,0)`，用 `AtlasTexture` 裁切、`STRETCH_KEEP_CENTERED` 保证像素对齐
- 选中态仍用 `modulate` 区分（1.0 / 0.45）

**3. 角色与地块的层级**

- 玩家在 `World`（z 10）下，`Soil` 为 z 5、`Watered` 为 z 6，角色本来就画在地块之上，实测站在苗圃上角色完整可见。
- 但发现真正的层级 bug：高亮框 `Cursor` 原为 z 0，**低于** Soil/Watered，高亮落到耕地上会被地面盖住。已把 `Cursor` 提到 `z_index = 20`。

### 开垦限制、动作表现与边界过渡（2026-11-02 追加）

**1. 开垦不能再随处点**

规则改为：目标格必须**紧邻已有耕地**（上下左右任意一格），且落在 `TILLABLE` 范围内。初始 4 块苗圃就是扩张起点，耕地会顺着边缘长出去，不会在草地中间凭空挖出一块。

- `_is_tillable()`：范围判定 + 已开垦判定 + 四邻至少一格是耕地
- 浇水本来就是"只对已开垦且未浇水的格子生效"，无需改动

**2. 使用工具的动作**

角色进入 `is_acting` 状态：锁移动、锁工具切换，总时长 0.34s，**命中帧（0.15s）才真正改地形**，不是点击瞬间生效。表现由三部分组成：

- 角色朝面向方向小幅前冲再回位（`_play_action_motion`）
- 目标格上方出现工具图标并做 0.16s 的下挥弧线，随后淡出（`_play_tool_swing`）
- 命中时喷 8 颗 CPUParticles2D 粒子（锄地是土黄、浇水是水蓝）

**3. 耕地边界过渡**

新增 `SoilFringe` 层 + 运行时生成的过渡图集：四张 16×16 的渐隐色带（贴耕地一侧最实、向外 6px 淡出，带轻微噪点）。每次地块变化后重算 3×3 邻域，空地上有耕地的方向就撒一层色带。效果是把"硬边"变成一圈柔和的土壤过渡。

> 试过用散点土屑，但 4 倍缩放下会像"草刺"，改成色带后才读得出是过渡。

**仍缺的素材（需要补充）**

1. **角色动作帧**：`basic_charakter_actions.png` 是 96×576，按 48×48 分块是 2 列 × 12 行共 24 帧，但**没有说明每帧属于哪个方向/哪个工具/第几帧**，无法可靠接入。需要：四方向 × 锄地/浇水各 3–4 帧的图集（或告诉我这张图的行列含义）。
2. **草地↔耕地过渡瓦片**：现有素材只有 blob 的角/边（整块草地色），没有任意形状的过渡，所以只能用程序生成的色带近似。若能提供一套 16px 过渡瓦片（4 向 + 4 角），可换成正规瓦片过渡。
3. **湿土贴图**（可选）：目前靠压暗 `modulate` 表现，若有专门的湿土贴图会更清楚。

- [ ] 金币不足买不了，且给出提示；背包满不会丢物品
- [ ] 卖价/买价可在一个 `.tres` 里改，改完立即生效
- [ ] HUD 数字与实际数据一致（买卖后立刻刷新）
- [ ] 商店关闭后角色输入恢复正常，不会"人物锁死"
- [ ] 连续 10 次买卖无金币错乱

### 明确不做

时间/天数系统（当前用调试按钮推进）、存档（关掉游戏进度就没了，属预期）。

## V0.7 能长期玩（时间、睡觉、存档）

**一句话**：有白天黑夜和天数，睡觉进入下一天，退出游戏进度不丢。

### 画面

- 左上角显示"第 N 天 06:00"，时间随游玩缓慢推进（例如 1 游戏小时 = 30 秒）。
- 到点后画面轻微变暗（傍晚/夜晚），角色可继续活动但作物不长。
- 走到床边/回屋按睡觉，弹出结算画面：今天收获、今天收入、进入第 N+1 天。
- 主菜单/暂停菜单：继续、新游戏、设置、退出。

### 玩家能做什么

- 看时间与天数，感受作息
- 睡觉推进到下一天，作物统一结算生长
- 随时暂停、存档、读档、返回主菜单
- 关掉游戏再打开，金币、地形、作物阶段、背包全部恢复

### 新增资源与文件

| 类型 | 路径 | 说明 |
| --- | --- | --- |
| 时间系统 | `scripts/time/time_system.gd`（Autoload 或单例节点） | 时/分/天、速度倍率、`day_changed` 信号 |
| 存档 | `scripts/persistence/save_system.gd` | 序列化：天数、金币、背包、`soil_grid`（地形+浇水+作物阶段）、玩家位置 |
| 存档格式 | `user://save_1.json`（或 `ConfigFile`） | 顶层带 `version` 字段，读档缺字段走默认值 |
| 结算 UI | `scenes/ui/day_summary.tscn` | 日报 + 确认进入下一天 |
| 主菜单 | `scenes/ui/main_menu.tscn` | 新游戏 / 继续 / 设置 / 退出 |
| 暂停 | `scenes/ui/pause_menu.tscn` | `Esc` 打开，暂停游戏树 |

### 验收标准

- [ ] 睡觉后作物按"是否浇过水"统一推进，天数 +1
- [ ] 任何时刻（耕作中、商店打开时除外）退出再进入，进度完全一致
- [ ] 存档带版本号；旧档缺新字段时能读、用默认值，不崩
- [ ] 存档文件损坏时不崩溃，提示"存档损坏"并允许新游戏
- [ ] 暂停时游戏内时间与动画停止，恢复后继续
- [ ] 从主菜单进入游戏到退出，主流程无卡死

### 明确不做

动物、引导、音频打磨（下一阶段）。

## V0.8 有第二条产出线（动物）

**一句话**：鸡会自己走动，每天下一个蛋，捡蛋卖钱。

### 画面

- 鸡舍前有 1–3 只鸡随机踱步，偶尔啄地；靠近会小幅避让。
- 每天早上鸡舍前或草地上出现蛋（`egg_item.png`），可拾取。
- 捡蛋时 HUD 背包条里蛋的数量 +1。

### 玩家能做什么

- 走到蛋上按交互键拾取
- 卖蛋（复用商店）获得第二条收入
- 观察到"鸡每天产一个蛋"的稳定节奏

### 新增资源与文件

| 类型 | 路径 | 说明 |
| --- | --- | --- |
| 动物 | `scenes/world/chicken.tscn` + `scripts/animals/chicken.gd` | 简单游走状态机（在鸡舍周围范围内随机点移动） |
| 产蛋 | `scripts/systems/animal_system.gd` | 监听 `day_changed`，在指定格生成蛋 |
| 蛋物品 | `data/items/egg.tres` + 拾取交互复用 V0.4 的交互系统 | 加入背包与商店卖价 |

### 验收标准

- [ ] 鸡在限定区域内游走，不会走出围栏、不会卡进建筑
- [ ] 每天最多产 1 个蛋，睡觉后必产，蛋不重复堆叠在同一格
- [ ] 拾取蛋后加入背包并可在商店卖出
- [ ] 5 只鸡同时活动不掉帧
- [ ] 存档后鸡的位置与当天是否已产蛋能正确恢复

### 明确不做

喂食、动物好感度、多种动物、繁殖（牛素材保留，作为后续扩展）。

## V0.9 能交给别人玩（引导、设置、帮助）

**一句话**：把游戏递给一个没看过设计的人，他能自己玩懂第一天。

### 画面

- 首次进入：农田区有一小片已经锄好的地，地上有闪光提示，两行以内的提示文字说明"按空格锄地"。
- 完成每一步后提示自动消失，不堆叠、不弹窗。
- `F1` 或暂停菜单打开"按键说明"：移动、交互、切换工具、背包、睡觉。
- 设置面板：主音量/音乐/音效三条滑条、窗口模式、语言（若做）、重置存档。

### 玩家能做什么

- 完全按自己的理解完成第一天：锄地 → 播种 → 浇水 → 睡觉 → 第二天收
- 自行查帮助、调音量、改窗口
- 不需要向任何人提问

### 新增资源与文件

| 类型 | 路径 | 说明 |
| --- | --- | --- |
| 引导 | `scripts/systems/tutorial_system.gd` | 步骤状态机，只推进不回头，进度入存档 |
| 提示条 | `scenes/ui/hint_bar.tscn` | 底部一行，自动淡出 |
| 帮助 | `scenes/ui/help_panel.tscn` | 按键速查 |
| 设置 | `scenes/ui/settings_panel.tscn` | 音量总线（Master/Music/SFX）+ 窗口模式 |
| 音频总线 | `project.godot` → `audio/buses` | 三条总线已建立并可调 |

### 验收标准

- [ ] 5 名陌生玩家中至少 4 人能独立完成第一天
- [ ] 没有人因为"不知道该干什么"停滞超过 2 分钟
- [ ] 所有设置项即时生效并在重启后保留
- [ ] 引导只出现一次，重开新游戏才重置
- [ ] 三种分辨率（1280×720、1920×1080、窗口化小窗）下 UI 不破版

### 明确不做

剧情、NPC、任务系统、多地图（这些属于 V1.0 之后的内容扩展）。

## V1.0 能发布（打磨与交付）

**一句话**：正式版本，画面、音效、数值、导出都到位。

### 画面

- 全部占位资源替换：像素字体、真正的 UI 边框（九宫格）、完整音效与 BGM。
- 每次操作都有反馈：挥锄头的土粒、浇水的涟漪、收获的弹跳与音效、金币飘字、睡觉的渐黑转场。
- 加载/开始时有一张简单的标题画面。

### 玩家能做什么

完整 7 天体验：从零开始，第 7 天拥有 4–6 块稳定产出的田、1 个鸡舍、可观的存款。

### 必做事项

1. 数值校准：第 1/3/7/14 天四个节点的金币、田块数、作物种类对比设计值
2. 反馈打磨：动作音效、粒子、飘字、转场、曲线缓动
3. 音频整合：BGM 循环无缝、音量分组、切场景淡入淡出
4. 字体与 UI：可商用像素字体，UI 九宫格，字号在 320×180 基准下清晰
5. 导出：Windows 导出预设、图标、版本号、启动画面
6. 干净环境验证：无编辑器环境下安装 → 游玩 → 存档 → 重启继续
7. 发布材料：截图 4 张以上、玩法说明、`CREDITS.md`（素材与字体许可）
8. 关闭调试：作弊键、调试面板、`print` 刷屏全部移除或加开关

### 验收标准

- [ ] 无任何占位资源
- [ ] P0/P1 bug 清零，60 分钟连续游玩无崩溃、无明显内存增长
- [ ] 干净机器全流程通过
- [ ] 所有素材许可可查
- [ ] 与 `01-游戏开发全流程.md` 阶段 9 的发布检查表逐项一致

## 每个版本的通用验收动作

每次交付一个版本，按顺序做完这四步再进下一版：

1. **跑起来**：编辑器内按 F5 运行，或 `godot --path e:/my-ai-game`。
2. **看控制台**：不允许出现 `SCRIPT ERROR` / `ERROR`；`WARNING` 记录后处理。
3. **截图比对**：按本文"画面"一节的描述逐条对照，截图存 `docs/screenshots/v0.X.png`（后续建立目录）。
4. **回写文档**：本版本实际与计划的差异（砍了什么、加了什么）写进该版本小节末尾的"实际记录"。
