## 文档维护规则

- 未来任务只改总纲，当前实现只改系统设计及对应专题；不在README或历史路线图增加第二份任务清单。
- 总纲第16节维护当前任务状态，开发记录只追加发生过的事实；不要从历史PASS或旧版勾选推断当前阶段已完成。
- 架构和目录规范维护约束，不重复粘贴逐轮成绩。原始报告保留日期、适用快照、命令与限制；自动检查、原生渲染、键鼠实玩、发行分别说明。
- 代码索引在[scripts](../scripts/README.md)，运行资源索引在[assets](../assets/README.md)，制作资料在[art](../art/README.md)。各目录README只维护本地入口和特有信息。
- `CODEBUDDY.md`只指向共享约定，不维护第二份环境、系统参数或测试命令。
- 更名或归档时同步相对链接；运行目录审计与文档链接检查。保留来源记录，不删除素材原图、清单、版权文件和验证JSON。

## 目录

`docs/`根目录保留本文及02–08七份当前文档。`history/`保存交付记录，`validation/`保存证据，`screenshots/`是带 `.gdignore` 的本地生成截图目录，默认不入库。旧文档统一进入 `archive/docs/`，不作为新的开发指令。

此次清理只调整文档及链接，不更改玩法、存档、素材或既有任务验收状态。整理范围和检查结果见[清理记录](validation/2026-11-06-docs-cleanup.json)。
