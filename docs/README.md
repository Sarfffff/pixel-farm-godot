## 文档编写约定

- 一份文档只解决一类问题，超过 400 行就拆分，文件名加编号前缀。
- 所有"要做的事"必须可验收：写清**怎么算完成**，避免"优化手感""完善 UI"这类无法判定的描述。
- 数值、路径、版本号写具体值，不写"若干""一些"。
- 决策变更时**改原文并补一行变更记录**，不要在文末堆叠"补充说明"。
- 涉及 Godot 决策（Jolt、D3D12、拉伸模式）的改动，先在文档里写理由，再动 `project.godot`。
