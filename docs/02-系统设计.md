# 系统设计：当前实现

整理日期：2026-11-06。本文件只描述当前运行机制和代码入口；未来范围、优先级与完成标准以[开发总纲](04-后续开发总纲.md)为准，开发约束以[架构规范](06-架构与开发规范.md)为准。

原文中早期版本、旧参数和重复“现状核对”已归档到[系统设计历史快照](../archive/docs/2026-11-06-before-consolidation/02-系统设计.md)。需要追溯旧算法、贴图取区或决策过程时查历史，修改代码时使用本文及实际配置。

## 1 实现边界

- 正式入口是标题场景 `scenes/ui/main_menu.tscn`，主游戏是 `scenes/main.tscn`。
- Godot 4.7.x；项目技术版本0.9.0不代表发布完成。当前基准视口640×360，默认窗口1600×900。
- 原农场40×30格，承担种植、商店、加工与睡眠；另有六个48×32格野外区域，共享同一玩家、背包、金币、日期与保存。
- 基础经营路径为种植、浇水、过夜、收获出售、采木石、升级水壶、购种再生产。主线章节、完整制作成长、动物经营及全年平衡仍按总纲推进。
- 自动逻辑、原生渲染、键鼠实玩和发行验收分别记录。既有结果见[验证证据索引](validation/README.md)，不能将素材数量或版本号当作玩法验收。

## 3 工具交互与河流地形

工具预览、可操作性和命中使用同一套判定。玩家起手时锁定工具、方向和目标，动画到命中帧才提交状态；失败操作不扣无效体力。正式工具信号由组合根交给区域适配器，再委派公开的 `begin_tool_action/commit_tool_action`；旧 `_on_*`回调只作兼容转发。

原农场用TileMapLayer分离地表、水体、道路、桥梁、装饰、耕地、湿土和边缘表现。河流与池塘有物理阻挡，桥面保留通路，地图有边界碰撞。逻辑格为16像素；贴图大小不能代替逻辑占地。

当前允许生产的范围由FarmTiller与地表规则决定。水、已有道路/桥面/坡地、建筑及实心障碍不能开垦。浆果和杂草的生成/恢复校验完整植物占地，避开不合适地表和玩家需要的种植空间；无法安全放置的旧浆果保留记录等待恢复，不能直接丢弃。

树木、树桩与石头分别提供有效命中入口。原农场最后一击先检查整批木材容量；满包保留目标，不扣失败命中的体力。资源状态与收益在命中时同步提交，倒树或清除动画只负责表现，因此动画中保存恢复不漏发或重复发奖。实心障碍变化通过信号请求导航重建。

原农场树木当前不新增自动再生，长期木石补给来自野外账本；免费杂草用于经营恢复。相关失败路径与连续多日补给见资源安全验证报告。

## 4 背包与物品

`Inventory`加载 `data/items/` 的ItemData，提供30格背包、8个快捷位和工具/种子/收获/材料分类。快捷位引用物品ID而非复制库存；数量、选中物品和工具提示保持同步。资源枚举使用 `ResourceLoader.list_directory`，兼容PCK中的重映射资源。

物品定义负责ID、名称、类别、堆叠上限、价格和图标；`add_item`返回未装入数量，取出、计数和容量查询共享同一份槽位状态。`begin_update/end_update`合并通知，观察者只应看到完整操作后的结果。

来源区分 `collection`、`purchase`、`transfer`，购买和从木箱取出不增加今日收获。工具不可通过普通出售/丢弃消失；开局和旧档恢复会确保基础工具存在。背包与快捷位的旧格式适配在Inventory自身恢复入口处理。

快捷栏说明框在创建时先确定文字换行宽度，再显示内容；面板尺寸变化后重新定位在快捷栏上方，避免首次点击时隐藏Label按零宽逐字计算出整屏高度。此为纯显示修复，不修改物品、输入绑定或存档。

B3共用库存端口`preview_exchange_batch(consumed, produced)`以临时槽位副本纯预演扣料后的净容量，返回`ok/reason`；`exchange_batch(consumed, produced, source)`预检后一次提交全部槽位，再发布合并通知。它支持外层`begin_update/end_update`，便于制作/放置服务先提交自己的事实；外层通知全部返回前拒绝其他交换重入。未知物品、非正整数、超限数量及基础工具输入/输出拒绝且不改库存；制作、摆放和返还不增加劳动收获统计。预演组件位于`scripts/inventory/inventory_exchange.gd`，不保存第二份库存，正式存档字段不变。三模块正式接线和B3整体回归仍在开发中。

## 5 作物与收获

收获用例对同格、跨格重入共享同步提交锁：先预检容量和体力，再批量提交库存、体力与作物移除/复收状态，最后发布库存、体力及完成通知。体力的嵌套`begin_update/end_update`只合并通知，数值仍同步更新；未进入批量边界的原调用保持即时通知。满包或体力不足保留作物且不发成功事件。教程使用的`harvest_info`在完成通知期间返回本次已提交收获的临时回执，通知后释放，不保存第二份作物或收益。

作物定义在 `data/crops/*.tres`，包含种子/产物ID、阶段图、每阶段天数、复收天数、产量和可播季节；实例保存阶段、阶段进度、浇水与复收状态。只在有效浇水日结推进，未浇水不生长；收获满包时保留成熟植株。

| 作物 | 可播季节 | 首熟所需有效浇水过夜 | 复收 | 每次产量 |
| --- | --- | --- | --- | --- |
| 胡萝卜 | 春、秋 | 3 | 无 | 1 |
| 番茄 | 夏 | 3 | 无 | 1 |
| 白萝卜 | 秋、冬 | 3 | 无 | 1 |
| 小麦 | 夏、秋 | 3 | 无 | 1 |
| 土豆 | 春、夏 | 2 | 无 | 1 |
| 蓝莓 | 夏 | 5 | 再浇水过夜2次 | 2 |

表中为整理时配置，不是固定日历成熟承诺；新数值先改Resource。播种和商店购种会检查季节，完整换季存活/枯萎与农业信息仍按总纲B1-06验收，不能由“已有季节字段”推断完成。

铜水壶配置在 `data/upgrades/watering_can.tres`：600金币、6木材、4石头，一次覆盖目标及两侧共三格，每次3体力。商店购买、能力判定、预览和实际浇水均读既有升级状态。

`FarmTiller.finish_day(rainy, sprinkled)` 预留了设备自动浇水的统一入口：`sprinkled` 是当夜设备实际覆盖且成功标记浇水的格子，只在非雨天补浇水，不改变手浇与雨天的既有语义；白天提示会区分“洒水器浇了 N 株”。主线程尚未注入任何设备来源，B3-04 接入前该参数始终为空。

## 6 交易、订单与社区

购买和出售走TradeService，读ItemData价格及原Economy钱包。购买资格通过注入规则检查社区解锁、季节和重复工具等条件；容量与金币先校验，完成后再发布成功事件。UI不维护第二份价格或扣款逻辑。

每日订单有期限和可行性筛选，不把尚未开放、当前无法新种的物品作为必需条件。社区按阶段交料、发奖励并解锁种子，表现层随同一社区状态修复围栏、摊位和招牌。引导手记跟踪首次收成、升级、购种再生产和第二轮出售，读档不回退已完成步骤。

这些是现有经营目标；完整修复集市的剧情章节、人物事件和长期奖励仍属于开发总纲。商店室内与NPC营业条件见对应场景/脚本，不在文档重复维护菜单节点编号。

## 7 时间、睡觉、体力与天气

TimeSystem使用天数和分钟，06:00开始、凌晨以24:00–26:00表示。标准速度为10游戏分钟/7现实秒；每季28天、每年112天，季节由日期推导。设置可调整时间流速。天气决定降雨等状态，体力负责有效操作消耗和恢复。

每日顺序由DailyCycle明确编排：结束当日生产 → 推进日期 → 更新次日天气 → 设置次日湿土 → 发布新日。晴天未浇水不会因次日下雨补长；次日晴天也不会残留前日雨水状态。

睡前View发出意图，DaySummaryPresenter提供统计和文案，RestController处理黑幕、床位和输入锁，RestService处理唯一结算：

- 18:00前上床小睡到20:00，日期不变、不执行跨天结算。
- 晚上上床进入次日，按原日结推进生产和恢复体力。
- 02:00累倒扣10%金币、上限1000，次日体力恢复至一半；野外返回农舍农场。
- 重复请求或信号只处理一次；先准备最终醒来落点再保存，保存失败提示且恢复输入。
- 移除睡前View不影响自动累倒；过场中销毁控制器会释放其输入锁和黑幕。

模型、Presenter和过场适配均由GameSession装配。RefCounted Presenter显式持有；移除Presenter后解除全部信号绑定。详细契约不在本文件复制，见架构规范。

## 8 存档与恢复

正式保存为v2、三个槽位 `user://save_<n>.json`，包含版本和元信息。SaveSystem使用SnapshotRegistry收集分区、SaveMigrations迁移v1、SaveStore隔离存储；临时文件完整写入并flush后替换，保留可恢复备份。未知高版本不假装兼容，写保护避免覆盖原档；标题界面关闭不写空进度。

| 分区 | 内容 |
| --- | --- |
| time、coins、inventory | 日期时间、钱包、背包和快捷位 |
| world_objects、farm | 显式稳定ID的树石状态、耕地与作物；v1石头字段只作迁移 |
| player、regions | 原农场兼容位置、活动区域/区域位置、野外资源损伤/再生/地面掉落 |
| coop、community、weather、stamina、upgrades | 蛋、社区、天气、体力和工具升级 |
| forage、berries、farm_activities | 采集、浆果、仓库、加工日期、钓鱼次数及寄存鱼获 |
| friendship、orders、tutorial | 好感、订单、引导状态 |
| quests | 章节任务的已接/已完成两张 `{任务id: 天数}` 表；旧档缺失时整章从可接开始 |

恢复顺序由组合根注册；输入结构与内层类型需要验证。恢复只还原状态，不执行砍树、采矿、交付或发奖。区域分区缺失的旧档初始化新增区域并回原农场，保留原田地；室内保存仍使用农场兼容位置。

新增设备/动物要先定义实例ID、创建配置与快照重建协议，当前单台加工设备和鸡蛋记录不能替代完整动态实例保存。

## 9 可进入的房子与区域

HouseManager缓存农舍/商店室内，隐藏原农场，将同一个玩家重新挂入当前World/Props层，切换相机边界和室内色调。主会话和核心系统持续存在；上床需在床边范围内。室内箱子复用原仓库服务。

WorldRegions使用原生蓝图构建六区，保留正式玩家，移除预览角色/UI。路线通过路标F交互，带淡出、内侧落点与区域名提示；未激活区域隐藏并停止节点处理，日结仍由主会话执行。

ResourceLedger维护资源纯状态，HarvestService验证工具/体力和整包容量，RegionInteraction适配起手锁定/命中帧，WorldRegions负责场景与碰撞。采完先落地，再按F拾取；满包保留整包，离区/跨日/读档保留掉落。大树在树脚落物，到期按蓝图原位再生，玩家占位时延后。

路线、28种资源、地表规格与具体数值只在[地图文档](05-地图类型与地面资源.md)维护。当前新地图主要用于采集探索，新增荒地不开放种植；村庄服务、剧情门槛、冶炼和新钓点仍按总纲推进。

## 10 木箱、采集、加工与钓鱼

活动布局/参数来自 `data/activities/farm_activities.tres`，配方来自 `data/recipes/`。FarmActivities保留世界道具与动画适配，长期依赖由组合根注入，不自行创建UI。

- 木箱为24格仓储。StorageTransferService协调背包/仓库，容量不足保留放不下的部分；模型通知发生时两边均已提交。室内箱子共享这一份仓库。
- 原农场有采集物和野浆果。具体补长数量、浆果占地与再生状态由各自配置/模型管理；免费恢复避开玩家和已耕地。野外资源走独立区域账本。
- 番茄腌制配方为3番茄、过夜1天、领取1番茄腌菜。ProcessingSession持有唯一完成日期，满包不消失，不能重复投入或领取；保存仍使用原加工日期字段。
- 基础钓鱼使用竹鱼竿，池塘钓点有鲫鱼/鲤鱼；每日3次、每次4体力，等待咬钩后收杆。FishingSession持有计时、状态与寄存鱼获；满包可保留待领取鱼获，关面板取消当前投竿。

FarmActivitiesPanel只接收显示快照和发布存取/钓鱼意图；FarmActivitiesPresenter整理列表、进度、按钮与提示。旧 `activities.panel`仅是注入View的弱引用兼容别名，移除或替换View不停止仓储、生产和恢复。

## 11 NPC、动物与鸡蛋

村民按日程使用格子导航，静态障碍按实际碰撞扫描并监听增删；对话、送礼和好感沿用原模型。营业条件与选项通过既有服务/对话入口处理。四位村民的头像按持久身份或场景映射选择，不为显示头像更改存档ID。

动物使用只读AnimalProfile、每个实例独立的AnimalStateMachine和FarmAnimal适配。状态可注册扩展，当前有游走、待机、觅食停留和睡眠；碰撞后短暂停留再选目标。玩家输入被模态锁定时，动物移动和计时一起暂停。

鸡的原图为单向：0为站姿、1为眨眼、2/3为空，4至7为四步循环；向左镜像，纯上下移动保留最近侧向。通用动物优先原生方向动画，缺少单侧步态时镜像另一侧，停步清除多余镜像；只有静态站姿的素材不能充作行走动画。

鸡舍按既有日结产蛋，地面蛋可保存，拾取满包保留。现有行为和产蛋不等于购买、成长、照料、容量和多物种经营已完成，B5状态仍以总纲为准。

## 12 界面、镜头与表现

ModalPanel与ModalCoordinator统一管理互斥、暂停、焦点、工具栏和模态输入锁；过场锁与模态锁分别维护。新面板注册即可，不在玩家脚本维护面板名表。复杂View使用MVP，简单输入适配不强制额外转发类。

相机跟随玩家、限制当前地图边界，窗口缩放与世界镜头缩放独立。背包、快捷栏和HUD读同一模型；主要UI共用 `assets/ui/farm_hud.tres`，主题、字体和图标不作为业务状态保存。

WorldPresentation根据现有日期和天气更新季节色调、雨雪/落叶、灯光、道路衔接与接触阴影；木箱开合、加工状态和NPC表情读现有状态，不增加另一套时钟或生产数据。资源遮挡与开垦排除使用可见像素边界和脚底碰撞。

音频和设置由platform模块及既有Autoload管理。音量、窗口模式和时间流速保存在 `user://settings.cfg`。应用退出统一清理音频、流和Tween，游戏关闭保存与标题关闭保留存档分别验证。

## 13 开发输入与发行隔离

`scripts/platform/development_controls.gd`接收开发输入，由组合根注入既有日结端口和可操作条件。普通源码运行默认关闭N跳天；仅编辑器源码显式传 `--enable-dev-tools`或启动器 `-EnableDevTools`才启用。开发日结不替代上床休息，不自动保存，不写偏好或新增存档字段。

## B1-06 换季作物与商店农业信息

露天作物在新日开始时依据当前季节应用规则：当日浇水/雨水先完成旧日生长，推进日期后，不适季植株变为不可逆枯萎；成熟未收和复收中的植株也会枯萎。跨季品种保留阶段与复收进度；空季节表按四季适种处理。温室尚未接入，仅在独立季节规则中保留受保护区域的扩展参数。

枯株不会继续生长、浇水、产出或复活。面向枯株按F免费清理，不要求体力或背包容量，保留已开垦地，不发收获事件。`Crop`保存可选 `withered` 布尔字段；旧v1/v2缺少字段时默认存活，再根据已恢复的日期校验。不适季旧植株会枯萎，已记录枯萎的植株不因换回适季恢复。正式版本仍为v2、槽位路径不变。

`crop_season_rules.gd`只计算季节、首收/复收夜数、当前季节剩余天数及首次收获风险；`seed_information_presenter.gd`将只读结果整理给商店，订阅新日与恢复完成，离树/替换时解除绑定。商店显示季节、首收、复收或单次产出、剩余天数，以及今种可首收/来不及首收/错季提示。行高按实际文字高度调整，详情在滚动区内完整显示。

季末仍允许购买当季种子，用于留种等选择；风险提示不替代交易资格。错季购买仍由原交易用例拒绝且不扣款。首收预算包含接下来的连续适季日期，因此夏秋作物可跨季，若成熟时恰好进入不适季则提示来不及。恢复完成只重建事实和信息，不补发奖励。

## B2-01 / B2-02 章节任务与第一章任务稿

章节目录式任务接入：`scripts/progression/quest_log.gd` 是模型（定义表 + 已接/已完成两张表），只推导 `LOCKED → AVAILABLE → ACTIVE → COMPLETED` 与前置条件，不认识背包、金币、界面或场景树；`scripts/progression/quest_service.gd` 是用例，接既有背包、钱包、日期与保存端口，负责接受、进度与交付事务。定义与台词全部在 `data/quests/*.tres`（`QuestData` / `QuestStep` / `QuestReward`，类在 `scripts/data/`），加一章只需加数据文件。

进度不存计数器：每次按背包当前持有量推导每一步的 `have/need`，读档、反复打开面板和重复交付都不会累计两遍。交付是一次事务：先确认全部交付步骤够数、奖励物品现在放得下，再进入 `busy`、扣货、提交模型、发金币与物品，最后 `end_update` 通知观察者；失败不改任何事实。重入保护覆盖重复按钮、重复信号与观察者回调，observer 在通知里再次提交会被拒绝，且它看到的一定是已完成状态与已发放的奖励。奖励物品被禁止与交付物相同（回归断言），使「扣货前判断容量」恒为保守正确。

接取与交付均立即尝试保存。写档失败由 `save_failed` 交给组合根，经 Toast 显示「任务进度已更新，但存档失败 · 请手动重试保存」；内存结果保留，不重复发奖。恢复只还原事实，不调用发奖入口；未知任务 id、非数字天数、已完成又挂在进行中的条目分别丢弃、回落到第 1 天、以完成表为准。

第一章内容（6 个任务、委托人、交付、奖励与三组台词）见[第一章任务稿](08-第一章任务稿.md)。现已接入NPC接受与交付对话；日志、过场和信箱按各自模块交付与主场景接入分别记录。

### NPC任务对话与整合端口

`quest_dialogue_presenter.gd` 整理委托台词、材料、奖励与确认选项。NPC通过组合根注入的 `quest_options` / `quest_response` Callable 转发意图；通用对话View只渲染 `lines/options` 显示快照，保留原有聊天、赠礼和商店行为。查看委托不自动接取，接取需确认，完成后不再提供重复交付。店主打烊时仍可谈委托，商品交易仍受原营业时间限制。

四位委托人具有显式稳定 `npc_id`；木匠与渔夫新增身份后也复用既有聊天/送礼好感记录，旧档缺少对应关系条目按0处理，不迁移或重发奖励。室内店主延迟创建时由组合根的节点创建绑定接线，NPC不在交互时查找任务服务。Presenter显式挂在Systems，解绑与离树时清除自己安装的两条端口；NPC销毁后旧对话按钮安全关闭。

任务服务保留 `accept/deliver/progress/can_deliver`，新增只读 `definition/delivery_hint` 和核对委托人身份的 `accept_for/deliver_for`。`can_deliver`只表示材料满足，最终操作还必须通过 `delivery_hint` 中的依赖与整批容量校验。重复材料需求合并后统一验证和扣除；`Inventory.has_space_for_batch`在库存模型内计算整批物品容量，共享空格不会重复计算。材料、完成事实、全部物品奖励先提交，再通知钱包和背包观察者；busy覆盖接受/完成/保存及其通知，拒绝回调内再次接受、交付或恢复状态。

`quests`分区移至基础模型与世界恢复后；恢复期间禁止玩法提交。正式保存格式仍为v2，没有新增NPC任务数据分区。日志、事件与章节结果的正式接线见下文；完整章节仍保留真人键鼠验收。

### 第一章正式会话整合

GameSession显式持有任务对话Presenter、任务日志Presenter、事件服务、过场执行器、章节流程与制作服务。日志通过K键或HUD按钮打开，Q/E仍切换工具、J仍打开农场手记。`quest_tracking`只保存唯一追踪ID，在quests之后恢复，缺失或非进行中目标清空；View不保存任务进度副本。

Player新增按owner持有的输入租约，和原有休息/模态锁取或；过场只释放自己的租约。模态协调器注入开门资格，在工具动作、手动过场锁、休息事务或剧情租约期间拒绝新面板，避免暂停过场自身。TimeSystem沿用玩家锁定时停止推进的语义。NPC与Player提供公开朝向适配端口，事件不跨模块修改私有朝向。

`events`在世界、任务及追踪之后恢复；SaveSystem在合法快照应用前发`restoring`，组合根先取消旧过场并清除待播队列，然后还原各分区。`restored`再次清队列，避免恢复中的区域信号排入新剧情。恢复不播放事件或投递新信；后续正常的对话关闭、区域变化、出屋或新日边界才重新评估。退出先释放过场租约/相机/黑幕并解绑表现，再清服务与快照回调。

新游戏自动投递无附件欢迎信。完成`ch1_06_lamps`后，`ChapterFlow`在农场户外、人物空闲且没有模态的正常边界投递`chapter_one_complete`，并播放一次`ch1_market_memory`。完整观看与跳过共享同一完成事实和来信，回应选项不改变奖励；关键结果与工作台资格不依赖动画结束。旧档已完成章节但缺少events/mail时，不在恢复过程中补发，下次正常玩法边界可补齐未触发内容。

集市表现读取唯一的任务事实：第一段完成显示告示，花坛段完成显示摊位，最后一段完成显示灯与灯光；恢复后按相同事实重建。不修改社区中心的交料/解锁等级，社区与章节对共用摊位/告示的可见性取或，章节点亮的灯单独跟随章节。碰撞变化通过组合根请求导航重建。

### 第一章工作台与留种

农舍现有`Props/CoffeeTable`在室内创建时注入`SeedWorkbench`交互，靠近按F打开制作面板。它是固定木桌的交互能力，没有动态设备实例或独立库存；开放资格直接读取最后任务已完成事实，不保存第二份解锁标记。

`CraftingRecipeData`存放即时配方，与按天加工配方分开；`CraftingService`统一校验解锁、材料及整批成品容量，完整扣料/入包后再通知和保存，观察者重入拒绝。首个配方在`data/recipes/carrot_seed_pack.tres`：胡萝卜×1、纤维×2 → 胡萝卜种子×4，成品复用现有播种系统，不计今日收获。背包放不下时保留全部材料；保存失败保留内存结果、显示提示，后续正常保存成功清除待保存标记。

## B2-04 条件事件与独立过场组件

`scripts/events/event_service.gd` 通过注入的只读查询端口验证地点、绝对日期、时段、天气、关系和任务条件，持有自己的稳定事件ID与完成日记录。`StoryEvent/StoryCondition/StoryCue` Resource 位于 `scripts/data/`，实例在 `data/events/`；目录扫描使用 ResourceLoader。服务在触发时同步记录完成并调用既有应用用例端口提交关键结果，随后请求保存；保存失败发可见信号，重复触发、观察者重入、跳过和重复恢复不会再次结算。

`cutscene_player.gd` 独立执行台词、直线走位、朝向、镜头、淡入淡出、回应选项和等待，可 Escape 跳过。完整观看和跳过共用同一份已提交结果，跳过应用剩余角色位置/朝向；取消只中止表现。选项当前是表现回应，不改变固定剧情结果，不在选项信号中发奖。默认 `cutscene_dialogue.gd` 与常规对话面板独立，可替换/解绑。

组件只持有自己的输入租约、129层黑幕、130层对话和临时相机，结束/取消/离树恢复自身占用与角色处理模式，不清理其他来源锁、全局ScreenFade或后来接管的相机。建议作为可选 `events` 快照分区在任务之后恢复，正式v2不变；恢复前先取消旧播放，不重播过场。

本次交付为独立模块，未修改正在并行开发的GameSession与DialoguePanel，也未自动接入第一章。正式输入租约仲裁、条件变化触发器、保存注册、角色动画/路线及章节表现仍需组合根整合，不能将模块检查当作第一章玩家流程已完成。完整接口及接线要求见[事件模块契约](../scripts/events/README.md)。

## B2-05 信箱与附件

`MailData`（`scripts/data/mail_data.gd`）定义稳定 `id`、寄件人、标题、正文、金币和 `Array[MailAttachment]`；附件定义 `item_id/count`。数据放在 `data/mail/*.tres`，通过 `ResourceLoader.list_directory` 发现，兼容PCK。`farm_welcome` 是不带附件的示例信，定义存在不代表已投递；章节条件和何时投递由B2-06整合层接线。

`mailbox_state.gd` 只维护投递日期、已读和附件已领取事实。`mail_service.gd` 负责投递、阅读、整批附件领取、重入保护与保存端口，不查询SceneTree/UI。`mailbox_presenter.gd` 整理显示快照并转发意图；`mailbox_panel.gd` 只负责渲染、选择和按钮。世界交互组件 `world/interactions/mailbox.gd` 仅显示未读标记并发出打开意图。信箱位于农舍东侧 `(512,168)`，复用现有原创信箱贴图。

### 供整合层调用的公开接口

组合根显式持有 `GameSession.mail`。公开端口如下，失败返回 `false`，领取失败说明见 `last_rejection`：

| 接口 | 行为 |
| --- | --- |
| `deliver(id)` | 已知定义只投递一次，记录首次投递日；不发附件 |
| `mark_read(id)` | 只把已投递信标为已读；重复调用不写档 |
| `claim(id)` | 领取整封信的金币和物品；已领、未投递或满包时不结算 |
| `claim_hint(id)` | 只读的领取限制说明；空字符串表示可领取 |
| `unread_count()` | 返回未读数，用于世界信箱标记和面板标题 |
| `letters()/definition(id)/status(id)` | 已投递定义列表、定义及状态副本 |
| `encode()/restore(data)` | 邮件事实编码与纯恢复；恢复不调用投递或领取、不写档 |
| `retry_save()` | 仅重试保存现有结果，不重新发奖 |
| `confirm_saved()` | 完整快照成功写入后清理未保存提示，不投递或领取附件 |
| `register_definition(data)` | 注册附加Resource；拒绝无效或重复稳定ID |

服务信号为 `delivered(id)`、`read(id)`、`claimed(id)`、`changed` 与 `save_failed`。剧情条件在整合层调用例如 `game_session.mail.deliver(&"farm_welcome")`，不能把任务、日期或好感条件写进邮件View。稳定ID禁止复用成另一封信；暂时缺定义的投递/领取墓碑也保留，防止资源恢复时重新发奖。

### 事务、保存与模态要求

附件同种物品先合并数量，使用 `Inventory.has_space_for_batch` 校验整批共享空槽；失败时金币、库存和领取标记全部保留。成功后在 `begin_update/end_update` 内先提交已领事实和全部物品，再增加金币，观察者看到完整结果。物品来源标记为 `mail`，不计入今日收获。`busy` 覆盖通知与写盘，重复点击及观察者回调不能再次投递、领取或恢复状态。

新增可选保存分区 `mail = {version:1, letters:{稳定ID:{day,read,claimed}}}`，正式槽位格式仍为v2。在日期、钱包和库存之后注册 `register_section(&"mail", mail.encode, mail.restore, TYPE_DICTIONARY, true)`；旧档缺分区清空信箱，读取已领记录不补发任何附件。写盘失败保留本次内存结算，`save_pending` 保持为真，组合根Toast与面板常驻文字/“重试保存”同时提示；重试不重放奖励。

`GameSession._configure_mail` 创建View与Presenter、注入服务端口并绑定世界信箱；将`SaveSystem.saved`接到`mail.confirm_saved`，从暂停菜单等其他入口保存成功也会清理未保存提示。View继承 `ModalPanel`、`pauses_world=true`，必须调用既有 `ModalCoordinator.register_panel(view)`，禁止另改玩家输入锁或时钟。信箱只在实际由关闭变为打开时发`opened`；被协调器拒开不会标记已读，正常打开只标记实际选中的信。关闭/面板切换由协调器释放暂停与输入。Presenter支持替换View并在离树时解除模型、背包和View绑定。

任务日志Presenter同时订阅`restored`及`saved`；成功保存只清理保存失败文案，保留材料不足等其他操作反馈。重复配置、View替换、离树和显式销毁均解除自己建立的保存绑定。

### 劳动凭据与能力应用

`LaborPort` 只转发技能服务的只读能力与成功凭据，不保存经验；经验唯一归 `SkillService`，同一凭据全局去重。

- 收获：作物物品、体力和作物状态提交后按 `harvest:<日>:<格X>:<格Y>` 记一次；满包与清枯株不记。
- 伐木/清桩：树倒时记 `chop:<稳定身份>:<命中前次数>`，清桩记 `stump:<稳定身份>`；动画期间不可命中，重复命中不重复计。
- 采集：农场杂草、浆果与区域资源在产出落地/入包后按 `forage|chop_tree:<区域>:<资源ID>:<日>` 记一次，工具映射为斧头→`chop_tree`、徒手→`forage`，石镐不计经验。
- 钓鱼：投竿起始固定一次 `fishing_parameters`，咬钩窗口本次有效；成功领取鱼获记 `fish:<日>:<当日投竿序号>`。
- 体力：`FarmTiller.tool_cost` 先取工具升级价再叠加技能减免，预检、实扣与提示共用；区域采集与活动钓鱼同样走端口；买卖、取箱、任务/邮件/制作和读档不产生经验。

### 制作资格、放置与保存

`_placement_query` 校验地面、水面、桥面、道路、耕地、门口/出入口、玩家所在格与真实静态碰撞（忽略正在移动的设备自身）。`allowed` 端口以设备类型存在为条件，放置消耗1件、拆除返还1件，设备之间重叠由服务自行判定。

保存顺序：日期/钱包/库存/技能 → 世界对象/农场/区域 → 设备 → 任务/事件；旧档缺分区安全默认为空，连续恢复不追加经验、物资或设备。`skills` 或 `devices` 拒绝不兼容数据时保留现有状态并提示，不把失败当恢复成功。正式槽位格式仍为 v2。

设备恢复失败、放置失败和保存失败均通过 `Toast` 可见，失败不丢物品、不产生幽灵碰撞；面板在 `save.restoring` 时关闭并清空预览，退出时先断开 Presenter 绑定再释放服务事实。

专项分工：技能的五级收益与正式基准对齐、凭据矩阵和劳动端口契约在 `tools/lib/skills_contracts.gd`（由 `check_skills` 注入断言），制作资格刷新与视图保持由 `check_crafting` 覆盖，放置端口契约镜像、工厂原子性与 `[F]` 分派提示由 `check_placement` 覆盖；真实场景的端口一致性仍由 `check_b3_integration` 兜底，三方都不以源码文本或节点数量代替行为断言。
