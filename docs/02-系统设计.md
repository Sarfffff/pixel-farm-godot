## 工具交互与耕地美术

### 本次选择

当前版本采用基础工具一次作用于面前一格的方式。空格与鼠标左键统一使用预览框中的目标，不根据鼠标远处的位置跨格作业。一按一次，按住不自动连发；后续有工具等级和体力系统时再加入范围蓄力。

起手时锁定工具、方向、目标格与目标树。角色播放工具动作，锄头和斧头切到第 2 帧、水壶切到第 1 帧（从 0 开始计数）时提交一次效果；随后保持命中姿势并收手。移动、工具切换和重复按键在本次动作结束前无效。角色动画是命中时机的唯一来源，不再使用与动画无关的延迟计时器。

锄头总长 0.44 秒，0.16 秒命中；斧头总长 0.46 秒，0.19 秒命中；水壶总长 0.54 秒，0.12 秒开始浇水。锄头与斧头使用独立生成的四向四帧图片：锄头向下入土，斧头横向砍击，朝上时工具作用于角色前方。水壶沿用原项目素材，产生水滴与短暂落地水纹。新图经过最近邻缩放、硬边 Alpha 和脚底基线整理，见 [素材索引](../assets/generated/README.md)。

### 开垦判定

- 种植区保持为格坐标 `Rect2i(16, 5, 14, 10)`，区内可独立开新田，取消必须紧贴旧田的限制。
- 已开垦地块不能重复开垦；水壶只浇**已种下的作物**（空耕地浇水没有收益，先播种再浇）。选择锄头时显示种植区的虚线边界。
- 不可开垦分为三类，按此顺序判定并给出对应提示：该格已铺小路/桥面/水面/坡地（图层占用）；该格被道具贴图覆盖，如树冠、屋檐、石头与原木（贴图包围盒内缩 2px 判定）；该格中心 14×14 范围内有真实碰撞体（建筑、石头、树干与树桩）。物理查询排除玩家自身。
- 因此树冠正下方不能再凭空翻地，木栈道与桥面也不会被锄头挖穿；砍倒后的树桩只保留脚底一格的阻挡，不再按旧树冠范围大面积禁止开垦。
- 目标格优先取面前一格；面前不可操作时，锄地/浇水/收获会在身边一圈（3×3 去脚下）按“面前 → 斜前 → 左右 → 斜后 → 身后”找一格，角色随之转向该格再出手（`resolve_target` + `player._face_cell`）。播种不参与范围选择，必须面向目标格。注意这仍是一次一格，只是省走位；一次多格的效果留给工具升级（Lv2 面前 1×3、Lv3 3×3），见 `07-作物与收获` 的后续项。
- 有效锄地/斧头目标为浅黄色，水壶为浅蓝色，无效目标为暗红色。动作进行时保留起手有效颜色。
- 顶部提示当前工具与不可操作原因，包括种植区外、地面已铺小路或桥面、上方有树冠或杂物遮挡、地面有障碍、已经开垦、已经浇水等。
- 数字键 3 是种子袋，播种动作暂时复用锄地的弯腰帧（`player.ACTION_ANIMATION`），命中帧一致。

### 土地外观

旧版给每格使用完整填充瓦片，并在草地上叠加半透明色带。这使外轮廓仍为直角，过渡又产生模糊感。

土地采用 `tilled_dirt_wide.png` 的原色板，单格是带 1px 小切角的方块，带两道浅垄纹。此前将大块土地的四个圆角缩进一格，会把单格挤成圆形，影响“一格能种一株”的判断；现在固定小切角，连片后消除内部边线。八邻域决定凸角、凹角与连接关系。图集已保存为 `assets/generated/terrain/soil_dry_atlas.png` 与 `soil_wet_atlas.png`。开垦后刷新周围九格，已浇水邻居的轮廓也会同步更新，并移除目标格的草地装饰。

湿土沿用土地的连边形状，以原项目的压暗色调区分。现阶段水分仅存在内存中，仍不包含跨天结算或存档。

### 砍树

按 `4` 选择斧头。判定针对树根，不以树冠作为点击区域；树根正好在格线上的情况允许从相邻方向命中。小树两击，大树和果树三击。每次命中产生木屑和摇晃，最后一击播放绕树根倒下的动作。倒下结束后使用同图集中的原生树桩素材，保留与根部匹配的小矩形碰撞，防止角色穿进树桩；此时掉落一批木材进背包。

**树桩可以再用斧头清掉**（一击，`choppable_tree.stump_hits_required`）：树桩播放一下拔起的小动画后淡出销毁，碰撞随之移除，再掉 1 根木材，脚下那一格恢复成可开垦的普通草地。这样做而不新增工具，是因为玩家看到树桩本来就会举斧，多一个"铲子"只会增加工具槽与教学成本；也不采用"砍完自动消失"，那会让"树桩挡路要先清掉"的空间记忆消失。

树木再生（砍完的树桩重新长回树）留到 V0.7 的天数系统，届时由每日结算决定是否重生。

### 同类游戏参考与取舍

- [《星露谷物语》官方 1.6 更新说明](https://www.stardewvalley.net/stardew-valley-1-6-update-full-changelog/)说明，升级锄头/水壶蓄力时允许角色横移，同时保持工具朝向。参考点是工具作用区应明确、朝向应稳定；本项目先完成固定单格和可靠命中，不提前引入升级蓄力。
- [《牧场物语 Welcome! 美丽人生》官方工具手册](https://www.storyofseasons.com/awl/manuals/ps5/08/)按工具定义用途，并将更大作用范围作为工具升级收益。其锄头还可砍树；本项目素材已有独立斧头，因此选择明确区分锄地与砍树。
- [《牧场物语 Story of Seasons》官方种植指南](https://www.storyofseasons.com/sos/farm5.html)将清除树木和石头、开垦、播种、浇水、收获分成明确步骤，其每块田包含九个种植空间。本项目借鉴“田块位置明确、障碍先处理”的原则，但维持一次开垦一格，采用方形土块，而非直接照搬九格田。可耕种区以虚线和状态文字说明。

“自由开新田、无效操作不空挥、动作期间完全锁定、每击命中帧才改变世界”是针对本项目当前阶段的设计选择，并非声称以上作品完全采用同样规则。

## 河流与地形

地图保持 40×30 格、每格 16×16 像素。北侧河流穿过西侧草地，向东弯入东南池塘，再从东边界流出。西北增加一块带土崖边缘的草坡，屋前木板小路连接种植区外侧、东西向桥与南侧桥。原有四块苗圃和出生点保留。


### 素材与画面

- 水面直接使用 `assets/game/tilesets/water.png` 的四帧动画，每秒 4 帧。
- 岸线来自 `grass.png`：以 8×8 象限组合 256 个邻域图块，处理外角、内角与转弯。透明角下方垫水，避免露出草地底纹。
- 木桥来自 `wood_bridge.png`：保留外侧护栏、端柱与木板纹理，仅重复桥面内部像素，将原本一格宽的桥扩为两格宽。
- 草坡来自 `hills.png`，小路来自 `paths.png`。所有贴图保持原色板和像素尺寸，使用项目现有的最近邻过滤。
- 原始素材包不改动。拼接结果位于 `assets/generated/terrain/river_shore_atlas.png` 与 `river_bridge_atlas.png`。

### 布局与碰撞

地形布局统一放在 `tools/lib/farm_landscape.gd`，地图入口仍是 `tools/build/build_farm_map.gd`。

| 区域 | 格子范围 | 行为 |
| --- | --- | --- |
| 东西向木桥 | x=9–16，y=15–16 | 连接西侧草地和农田外侧小路 |
| 南北向木桥 | x=21–22，y=21–25 | 连接池塘北岸和南岸 |
| 西北草坡 | x=2–6，y=5–9 | 装饰性高地，崖壁阻挡移动，暂不提供上坡入口 |
| 原有种植区 | x=16–29，y=5–14 | 保留原有锄地、浇水判定 |

222 个水格共享同一份数据生成画面和碰撞。桥面覆盖的水格移除水碰撞，并添加侧面护栏碰撞，允许沿桥双向通行。岸线图层负责视觉过渡，河道内部始终不可步行。移动了落入河道的旧道具及挡住桥口的树木。

南北桥的宽度固定为两格，因此两处细节必须同步：

- 水域在 `x=21` 的 `y=20–21` 收回到岸边，让 `x=21–22` 两列同时从 `y=22` 开始有水；否则两格宽的桥会有一半压在岸上，桥头看起来歪向一侧。
- 引路同样铺满两格并接在桥头（北侧 `x=21–22, y=18–20`，南侧 `x=21–28, y=26–28`，遇水格跳过）。南北走向的引路使用 `paths.png` 第 0 列的横板图块，水平路段用第 3 行的竖板图块，混用会拼成一截截错开的木棍。

引路与桥面在铺瓦时被排除在可开垦范围之外，锄头不会把小路的木板挖掉。

## 背包与物品

V0.6 的前置系统：先有"物品能进能出"的容器，收获、商店、存档才有落点。当前版本只做**背包本体 + 砍树产出**，商店与买卖留到下一步。

### 数据

物品是数据驱动的 `Resource`，新增物品只加文件、不改代码。

| 文件 | 作用 |
| --- | --- |
| `scripts/data/item_data.gd` | `class_name ItemData extends Resource`：`id`、`display_name`、`description`、`icon`、`max_stack`、`sell_price`、`category` |
| `data/items/*.tres` | 8 个物品定义；背包在运行期扫描该目录 |

现有物品：

| id | 名称 | 分类 | 堆叠 | 参考售价 | 来源 |
| --- | --- | --- | --- | --- | --- |
| `wood` | 木材 | material | 99 | 8 | 砍倒树木（小树 2、大树/果树 3） |
| `stone` | 石头 | material | 99 | 5 | 待接入 |
| `fiber` | 纤维 | material | 99 | 3 | 待接入 |
| `fertilizer` | 肥料 | material | 99 | 12 | 待接入 |
| `carrot_seeds` | 胡萝卜种子 | seed | 99 | 4 | 开局随身 5 个 |
| `tomato_seeds` | 番茄种子 | seed | 99 | 6 | 待接入 |
| `carrot` | 胡萝卜 | crop | 99 | 25 | 待收获玩法 |
| `tomato` | 番茄 | crop | 99 | 35 | 待收获玩法 |

图标全部取自 `assets/generated/items/`（16×16，最近邻）。

### 系统

`scripts/systems/inventory.gd`（`class_name Inventory`，挂在 `Main/Systems/Inventory`，加入 `inventory` 组）：

- **30 格**（`SLOT_COUNT = 30`）；每格是 `{ id, count }`，空格为 `{}`。
- **快捷位 8 格**（`HOTBAR_SIZE = 8`），只存物品 id 不复制数量，默认 `锄头 / 水壶 / 胡萝卜种子 / 斧头 / 石镐 / 空 ×3`。
- **四件永久工具**（`TOOL_IDS`）：锄头、水壶、斧头、石镐，强制占位且不可取出（`remove_item` 对工具 id 直接返回 false）。
- `add_item(id, count) -> int` 先补已有堆叠再占新格，**返回没放下的数量**（满包时调用方负责提示，不静默丢物品）。
- `remove_item(id, count) -> bool` 数量不足时整笔取消，不做部分扣除。
- 查询：`count_of`、`item_at`、`definition`、`slot_count`、`total_items`。
- 信号：`changed`（UI 刷新）、`item_added(id, count)`（飘字提示）。
- 未定义的 id 直接退回并 `push_warning`，不会写进背包。

初始物品写在 `STARTING_ITEMS`（当前是 5 个胡萝卜种子）。播种玩法接入后改为从商店购买。

### 界面

`scenes/ui/inventory_panel.tscn` + `scripts/ui/inventory_panel.gd`，沿用工具栏的像素 UI 语言：

- 边框与槽位来自 `assets/generated/ui/inventory/inventory_theme.tres` 的九宫格像素贴图（`tools/art/prepare_inventory_art.gd` 生成）：`PanelContainer/styles/panel` 是木质外框，`InventorySlot/styles/idle|hover|selected` 是槽位三态，`InventoryDetails` 是底部米色说明框，`InventoryHint` 是灰字小号变体。
- 根节点是全屏 `Control`：底下铺一层 35% 深色遮罩（点击即关闭），中间才是木质面板。面板 132×148（原生 320×180 视口下约占 41%×82%）。
- 6 列 × 5 行（共 30 格）、每格 18×18（图标 16×16 + 1px 内边距），数量角标 7px 贴格子右下、带描边。
- 分类页签 5 个：`全部 / 工具 / 种子 / 收获 / 材料`（`CATEGORIES`）。分类页只做格子映射，不移动背包里的真实数据。
- 字体统一 `SystemFont`（微软雅黑 / Noto Sans CJK），标题 8px、正文 7px、角标 7px；说明框用深棕字保证米色底上的可读性。
- 选中格换选中态贴图，鼠标悬停换悬停态；底部显示"名称 ×数量"与说明文字，说明自动换行。
- 标题显示 `背包 已用格/总格`，标题栏右侧提示 `B / Esc / 点空白关闭`。

操作：

| 输入 | 行为 |
| --- | --- |
| `B` | 打开 / 关闭背包 |
| `Esc` | 关闭背包 |
| 点击面板外的空白 | 关闭背包（全屏遮罩接住点击，槽位与面板本身不会误关） |
| 方向键 | 在选择格之间移动（上/下跨 6 格） |
| 鼠标左键 | 选中格子，查看说明 |

### 与其他系统

- **输入锁**：面板打开时调用 `player.set_input_locked(true)`，角色停止移动并忽略工具输入；关闭时恢复。`player.gd` 的 `_physics_process` 与 `_unhandled_input` 都会检查该标记。
- **工具栏**：打开背包时调用 `toolbar.set_ui_visible(false)`，把工具栏与左上角提示条一起收起（提示条是 UI 的兄弟节点，只隐藏工具栏会盖住面板标题）。
- **入包提示**：`scenes/ui/toast.tscn` + `scripts/ui/toast.gd`，订阅 `item_added`，在工具栏上方浮出 `+N 物品` 并淡出；背包面板打开时不飘字，打开瞬间会 `clear()` 掉残留提示。
- **砍树掉落**：`choppable_tree.gd` 在树倒下的 `_leave_stump()` 之后按 `hits_required` 发木材（小树 2、大树 3），背包满时 `push_warning`。

### 验收


- `smoke_check`：`toggle_inventory` 输入存在、8 个物品定义完整（id/名称/图标）、main 场景含 `Systems/Inventory` 与 `UI/InventoryPanel`、玩家有 `set_input_locked`。

## 作物与收获

V0.5 的播种 / 生长与 V0.6 的收获打通：种子 → 幼苗 → 成熟 → 收进背包，闭环的第一段跑通。金币与商店仍是空白。

### 数据

| 文件 | 作用 |
| --- | --- |
| `scripts/data/crop_data.gd` | `class_name CropData extends Resource`：`id`、`display_name`、`stages`（阶段贴图数组）、`seed_item`、`harvest_item`、`harvest_count` |
| `data/crops/carrot.tres`、`tomato.tres` | 两种作物；`stages` 是“发芽 → 幼苗 → 生长 → 成熟”四张 32×32 贴图 |
| `assets/generated/crops/` | 阶段贴图（按 `crop_growth_v1.png` 图集切出，胡萝卜/番茄/芜菁/小麦各 6 阶段，后两种暂未配 `.tres`） |

加新作物：复制一个 `.tres`，换 `id`、`seed_item`、四张阶段贴图即可，不改脚本。

### 作物节点

`scenes/world/crop.tscn` + `scripts/world/crop.gd`：

- 32×32 `Sprite2D`，`offset = (0, -16)` 让贴图底边落在格子底边，向上占两格。
- 位置由耕地系统设成“格中心 + 8px”，挂在 `Farm/World`（y 排序）下，与角色、树木同一套遮挡顺序。
- 状态：`stage`（0 起）、`watered`（当天是否浇过）。`water()` 未成熟且当天没浇过时推进一阶并弹一下；`is_mature()` 为 `stage == 最后一张贴图`。
- `play_harvest()` 缩放淡出后自行 `queue_free()`。

### 耕地系统接入

`scripts/world/farm_tiller.gd` 新增 `_crops`（格坐标 → 作物）与 `_crop_definitions`（运行期扫描 `res://data/crops`）。

| 操作 | 条件 | 结果 |
| --- | --- | --- |
| 播种（`seeds` 工具） | 该格已开垦、没有作物、背包里有种子 | 扣 1 个种子，生成作物（stage 0），土变干 |
| 浇水（`watering_can`） | **该格有作物**、未成熟、当天没浇过 | 推进一阶，土变湿 |
| 收获（`E`） | 该格作物已成熟 | 收获物进背包，作物播放消失动画，土变干可补种 |
| 锄地（`hoe`） | 该格有作物时一律拒绝 | 防止一锄头铲掉作物 |

**空耕地不能浇水**：当前没有“湿土保持到第二天、省一次浇水”的机制，空地浇了也没有任何收益，只会让玩家误以为“先浇地再种有用”。等 V0.7 有天数系统、湿土能跨天保持时再放开。

### 作用范围与转身

锄地、浇水、收获支持**身边一圈（3×3 去掉脚下）**，播种仍然只作用于面前一格（避免把有限的种子撒错格）。

选目标的顺序（`farm_tiller.resolve_target`）：

1. 面前那一格可用 → 直接用，行为与以前完全一致；
2. 否则按 `面前 → 斜前 → 左右 → 斜后 → 身后` 的顺序，取第一个真正可操作的格子；
3. 一个都没有 → 仍返回面前格，光标变红并给出原因。

动作起手时角色会**转向目标格**（`player._face_cell`），播放对应方向的动画，命中的格子与转身方向一致。这样站在田中间就能连续处理一圈，不必走位对齐；想精确操作某格时，只要先面向它即可。

播种不走范围选择，是因为种子是消耗品，误种不可撤销；成熟作物被周围自动选中则没有这个风险（背包满时还会保留作物）。

- **种子选择**：种子袋只有一个槽位，直接取背包里第一种 `category == seed` 的物品（按格子顺序）。之后接商店可改成“手里拿哪种种子”。
- **背包满**：收获时 `add_item` 返回溢出数量，此时作物**保留在田里**，不会凭空消失。
- **满包/无种子**：提示文案会明确指出原因，不静默失败。
- 作物不会被认成“遮挡开垦的道具”（`_has_prop_overlay` 跳过 `Crop`），所以种满一格的作物不会挡住旁边格的开垦。

### 动作与输入

| 输入 | 行为 |
| --- | --- |
| `空格` / 左键 | 用当前工具（锄地 / 浇水 / 播种 / 砍树） |
| `E` | 收获面前（或身边一圈里）成熟的作物（`interact` → `_try_interact`）；`E` 同时绑着 `tool_next`，只有这一圈没有可收获对象时才回落到切换工具 |
| `N` | **临时调试键**：推进一天，清掉所有作物的浇水标记。V0.7 接入时间系统后由它接管 |

播种沿用锄地的弯腰动画（`player.gd` 的 `ACTION_ANIMATION` 把 `seeds` 映射到 `hoe`），素材里还没有单独的播种帧。命中帧与锄头一致，第 2 帧提交。

### 提示文案

| 目标格状态 | 顶部提示 |
| --- | --- |
| 作物已成熟 | `胡萝卜 已成熟 · 按 E 收获` |
| 作物浇水当天 | `今天已经浇过水 · 明天再浇` |
| 作物未浇水（水壶） | `给胡萝卜浇水 · 空格 / 左键` |
| 作物未浇水（其它工具） | `胡萝卜 正在生长 · 切换水壶浇水` |
| 空耕地（水壶） | `这片地还没有作物 · 先播种再浇水` |
| 空耕地（种子袋） | `播种 胡萝卜种子 · 空格 / 左键` |
| 未开垦（种子袋） | `先用锄头开垦这一格` |
| 没有种子 | `背包里没有种子 · 按 B 打开背包` |

## 经济与商店

V0.6 的闭环收尾：种 → 收 → 卖 → 买种子 → 再种。金币是唯一的全局数值，商店只是它的读写界面。

### 金币

`scripts/systems/economy.gd`（`class_name Economy`，挂在 `Main/Systems/Economy`，加入 `economy` 组）：

| 成员 | 说明 |
| --- | --- |
| `coins` | 当前金币，初始 500（`STARTING_COINS`） |
| `can_afford(cost)` | 够不够钱（负数一律视为不够） |
| `spend(cost) -> bool` | 扣钱，钱不够时**不做任何改动**并返回 false |
| `earn(amount)` | 进账，≤0 直接忽略，避免调用方写错把金币扣掉 |
| `changed(coins)` | 任何数值变化后发出，HUD 与商店都订阅它 |
| `coins_gained(amount)` | 只在进账时发出，供 HUD 飘 `+N` |

### HUD

`scenes/ui/hud.tscn` + `scripts/ui/hud.gd`：右上角一枚金币图标 + 数字，复用背包的米色九宫格样式（`InventoryDetails`）。收入时在数字下方飘一个 `+N` 并淡出。只读 `Economy`，不持有状态。

### 商店

`scenes/ui/shop_panel.tscn` + `scripts/ui/shop_panel.gd`：

- **左列买入**：物品表里所有 `buy_price > 0` 的物品（当前是胡萝卜种子 8、番茄种子 12）
- **右列卖出**：背包里所有 `sell_price > 0` 且持有数量 > 0 的物品，行尾显示「单价 × 持有数」
- 交易规则：点击行 = 交易 1 个；按住 `Shift` 再点 = 一次处理整批（卖光持有 / 买到买不起或背包装不下为止）
- 键盘：`↑` `↓` 选择、`空格`（`use_tool`）交易、`Esc` / 点面板外空白关闭
- 底部一行反馈最近一笔：「买入 胡萝卜种子 ×1（-8）」「卖出 木材 ×5（+40）」，失败时显示「金币不足或背包已满」
- 面板打开时锁玩家输入、收起工具栏与左上提示条，并与背包**互斥**（打开一个会自动关闭另一个，避免两个面板抢输入锁）

### 数据来源

商店不写死商品，全部来自物品表：

| 字段 | 作用 |
| --- | --- |
| `buy_price` | >0 才会出现在买入列，数值即买价 |
| `sell_price` | >0 且持有 >0 才出现在卖出列，数值即卖价 |

改价只改 `data/items/*.tres`，加商品只加物品文件，`shop_panel.gd` 不用动。

### 进入方式

早先放在门口地上的钱袋子（`shop_stand`）已经移除，商店入口完全交给老板 —— 详见 [NPC 与对话](#npc-与对话)。

`player.gd` 的 `E` 有优先级：**先收成熟作物**（面前优先、其次身边一圈），没有作物时再看附近有没有 `interactable`（老板、睡觉点）；两者都没有才回落成「切换工具」（`E` 与 `tool_next` 共用一个键）。

## 时间、睡觉与存档

V0.7 的第一块：有了日期与作息，作物从"浇水立刻长"改成"睡一觉才长"，退出游戏进度不丢。

### 时间系统

`scripts/systems/time_system.gd`（`Main/Systems/Time`，`time` 组）：

| 成员 | 说明 |
| --- | --- |
| `day` / `minutes` | 天数与当天分钟数（06:00 起床，26:00 = 次日 02:00 累倒） |
| `minutes_per_real_second` | 每现实秒推进多少游戏分钟，**可配置**：星露谷 10/7 ≈ 1.43（默认，一天约 14 分钟）/ 标准 2.0（约 10 分钟）/ 快 4.0（约 5 分钟）；由设置面板「时间流速」写 `AppSettings.time_speed` |
| `time_changed(day, minutes)` | 每变化一次游戏分钟发一次，HUD 与昼夜色调订阅 |
| `day_started(day)` | 睡觉结算时发出，耕地在这里让作物生长 |
| `day_over` | 到 02:00 时发出一次，`DaySummary` 据此执行星露谷式「累倒」：扣 10% 金币（上限 1000）、次日清晨醒来、体力只回一半，全程无弹窗 |
| `sleep()` | 日期 +1、时间回到 06:00，然后广播 `day_started` |

时间本身不存档也不碰界面，只发信号。

### 昼夜观感

`scripts/world/day_night_tint.gd` 挂在 `Main/DayNightTint`（`CanvasModulate`）：17:00 起逐渐变暗，21:00 达到最深（混入 55% 夜色蓝），保持到收工。`CanvasModulate` 只影响世界层，UI 的 `CanvasLayer` 不受影响，所以面板与 HUD 始终清晰。

### 作物按天生长

生长从"浇水即推进"改成星露谷式结算：

1. 水壶浇在作物上 → 只打 `watered` 标记，土变湿，提示「浇过水 · 睡一觉就长一阶」
2. 同一天不能重复浇（水壶对该格失效）
3. 睡觉 → `begin_new_day()`：**浇过水的作物 +1 阶**，然后清掉标记、土变干
4. 没浇水的作物睡一觉不长

`Crop` 的接口随之拆开：`water()` 只标记，`grow_if_watered()` 在结算时推进，`apply_stage()` 供读档恢复阶段。

### 睡觉与日报

- `scenes/world/sleep_spot.tscn`：**已搬到室内床脚**（室内场景的 `BedSpot`，半径 30px），提示「按 E 上床睡觉」。门口现在是"进屋"，睡觉必须先回家 —— 详见「可进入的房子 · 睡觉」。
- `scenes/ui/day_summary.tscn`：`第 N 天结束` + 今日收获件数 + 今日收入 + 金币余额，底部「睡觉 · 进入下一天」按钮；`E` / `Enter` 确认，`Esc` 或点空白取消
- 商店摊位挪到门口右侧（`ShopStand` at 488,152），与进门交互点分开，按 E 时取最近的一个

今日统计：`Economy.today_income`（`earn` 累加）与 `Inventory.today_collected`（`add_item` 累加），都在 `day_started` 时清零。

### 存档

`scripts/systems/save_system.gd`（`Main/Systems/Save`，`save` 组）：

- **三个槽位**：`user://save_1.json` ~ `save_3.json`，顶层带 `version`（当前 1）与 `saved_at`（unix 秒）
- 内容：`time{day,minutes}`、`coins`、`inventory.slots[]`、`farm{tilled[],watered[],crops[]}`、`player{x,y}`
- 当前槽位：主菜单选好后 `use_slot(slot)` 写进 `Engine` meta（`pending_save_slot`），进农场时 `SaveSystem` 读它，之后的保存都写这个槽位
- 时机：睡觉后自动存、关闭窗口时存（`NOTIFICATION_WM_CLOSE_REQUEST`）、启动时自动读当前槽位
- 容错：文件损坏 → 复制成 `save_N.json.broken` 并删除原文件，该槽位按空档处理；缺字段 → 各系统退回默认值；未知物品 id 与越界格坐标跳过
- 测试用 `SaveSystem.autoload_enabled = false` 关掉自动读档（实例化后立刻设置，早于 deferred 读档）

#### 主菜单选档

「继续游戏」不会直接进游戏，而是先弹槽位列表，每行两行文本：

```
存档 1 · 我的农场                        [改名] [删除]
第 1 天 · 500 金币 · 11-03 16:40
```

第一行是槽位号 + **农场名**，第二行是进度与保存时间；空槽位在继续模式下置灰。「新游戏」走同一个列表，标题变成「存到哪个槽位？」，选中已有存档的槽位会提示「（将覆盖）」。

**新游戏起名**：选完槽位先弹「给农场起个名字」，输入框预填「我的农场」（第 2、3 槽位是「我的农场 2/3」），回车或点「确定」才真正开局；名字写进存档的 `name` 字段，长度上限 16 字（`_name_input.max_length`）。新档进游戏时会先落一次盘，所以标题界面立刻能看到名字与天数。

**改名**：已有存档的行带「改名」按钮，复用同一个命名面板，只重写 `name` 字段、不动进度（`SaveSystem.rename_save`）。

**删除存档**：有档的槽位行右侧带「删除」按钮，点一次变成「确认?」，再点才真的删（防止误触），删完标题提示「已删除存档 N」并重建列表；空槽位不显示删除入口。删除只影响该槽位，其他槽位不受影响；全部删完后返回主菜单，「继续游戏」会自动置灰。

槽位信息由 `slot_summary(slot)` 现场读文件解析，不额外维护索引文件 —— 存档坏了也不会让标题界面崩。存档名存在 JSON 的 `name` 字段里，旧档没有这个字段时显示默认的「我的农场」。暂不做「存档复制」：三个槽位各自独立，复制对单人农场玩法没有实际价值。

各系统提供序列化接口：`Inventory.to_dict/from_dict`、`FarmTiller.to_dict/from_dict`，时间与金币由 `SaveSystem` 直接读写字段。

### 标题与暂停

- **标题界面** `scenes/ui/main_menu.tscn`（项目主场景）：`小农场` + 「继续游戏 / 新游戏 / 退出」。有存档时「继续」可点并默认聚焦，无存档时置灰、焦点落到「新游戏」。新游戏会先删除旧档再进农场，避免刚开局就被旧存档覆盖。
- **暂停菜单** `scenes/ui/pause_menu.tscn`（`Main/UI/PauseMenu`）：`Esc` 打开，`get_tree().paused = true` 停住时间与世界，面板自身 `PROCESS_MODE_ALWAYS` 保持可交互。三个选项是「继续游戏 / 保存游戏 / 保存并返回标题」；`Esc` 或「继续」恢复，返回标题前会先存档。
- **Esc 优先级**：背包 / 商店 / 日报任一打开时 `can_pause()` 返回 false，Esc 交给面板关闭；都关闭时才弹暂停。这样不会出现「关面板同时把游戏也暂停了」。

### 村民寻路与多句对话（2026-11-04 追加）

**寻路为什么用格子 A* 而不是 NavigationRegion2D**

全项目坐标都以 16px 格子为基准，道具碰撞是固定的小矩形/圆。用 `AStarGrid2D` 直接按格标记：

- 不需要烘焙导航网格，改地图不用重新 bake
- 能在无窗口自检里跑通（`check_npcs` 断言路径存在、水面不可走）
- 天然和"一格一步"的农场尺度对齐

`scripts/world/nav_grid.gd`（`class_name FarmNav`，挂在 `Farm/Nav`，由生成器创建）在 `_ready` 里 `call_deferred` 扫描三样东西标成不可走：

| 来源 | 处理 |
| --- | --- |
| 地图边界 | 最外一圈固定封死 |
| `WaterCollision` 图层的格子 | 整个池塘 |
| `World` 下所有 `StaticBody2D` 的碰撞形状 | 按矩形/圆取包围盒并外扩 2px（`CLEARANCE`），树、房子、石头都算 |

对外 API：`find_path_cells()`、`nearest_walkable()`（目标被占时螺旋找最近可走格）、`random_walkable_near()`（闲逛用）、`is_walkable()`。

**村民行为**

`scripts/npcs/npc.gd`（`class_name VillageNpc`，Sprite2D 根节点，保持和原素材 4 帧四向表一致）：

- 日程是 `routine: Array[Vector2i]`，按顺序循环走；留空则在 `home_cell` 附近随机踱步
- 沿路点逐点靠拢，不走物理：NPC 没有碰撞体，玩家可以穿过（小地图里被 NPC 堵路比穿过去更烦）
- 到达后停 `wait_seconds`，再规划下一个目标
- 朝向用帧序号切换：`0 下 / 1 上 / 2 左 / 3 右`
- 对话打开、暂停菜单、玩家被面板锁输入时，NPC 站住不动

**多句对话**

- 不是最后一句时只给「继续」，逐句推进

- 选项仍回调 NPC 的 `on_dialogue_option(id)`，商店老板走原来的单句 `open_with()` 路径不受影响

## 可进入的房子

**一句话**：走到农舍门口按 E 进屋，屋里有床可以睡觉，走到门里按 E 回农场。

### 为什么不做场景切换

`change_scene_to_file()` 会把 `Main` 下的时间、背包、经济、存档等 Systems 全部重建，时间和背包状态当场丢失。所以：

- 室内场景作为 `Main` 的**兄弟节点**，放在 `Vector2(0, 2000)` 的远处（`HouseManager.INTERIOR_ORIGIN`）
- 进出屋只做三件事：**隐藏农场 / 显示室内**、**把玩家 reparent 到当前世界**、**换相机边界**
- 两套世界在坐标上互不重叠，农场的碰撞体即使存在也碰不到玩家

玩家 reparent 而不是简单改坐标，是为了让 Y 排序与可见性跟着世界走——农场隐藏时玩家也不会跟着消失。

### 室内怎么来

`assets/generated/` 里只有建筑外观、没有室内图，所以室内是**用现有素材拼的**：

| 图层 | 素材 |
| --- | --- |
| 地板 | `terrain/interiors/wood_floor.png`（16×16 平铺） |
| 墙 | `wood_wall` / `wallpaper` / `wall_trim`（顶墙三行：木墙、壁纸、踢脚线） |
| 家具 | `objects/furniture/`：床、衣柜、餐桌、橡木椅 ×2、方毯、壁炉、盆栽蕨 |

房间 **27×19 格（432×304 px）**，底墙中间留两格门洞，门洞下方再补 3 排实心墙（见下）。场景由 `tools/build/build_house_interior.gd` 生成，改家具位置只改脚本里的 `FURNITURE` 表再跑一次。

尺寸不是随手定的，是被相机与 HUD 挤出来的：

1. 宽度 432 让相机最小缩放落在 **1.5**（`max(640/432, 360/304)`），一间屋横向刚好铺满，不出现"半面墙被裁掉"；
2. 高度 304 比画面高，相机能**上下轻微滚动**，站着看床和走到门口是两个画面，屋子不像一张静态贴图；
3. 门洞下面那 3 排墙是为了把门"顶"到底部工具栏上方——`interior_bounds` 高度取 352（19+3 格），相机滚到最底时门是可见的。

### 墙体碰撞（2026-11-04 补）

**实机试玩发现的问题**：室内只有家具碰撞，四面墙是纯贴图。按住方向键可以从房间内部一路走到 `x = 1057`、`y = -528`——直接走进虚空，相机还被锁在房间里，人就不见了。

修法是在生成器里加一个 `WallBody`（`StaticBody2D` + 4 个矩形），把可走区域围成封闭盒子：

| 碰撞体 | 范围 | 说明 |
| --- | --- | --- |
| `Wall0` 顶墙 | `y 0–48` 全宽 | 挡住往上走 |
| `Wall1` 左墙 | `x 0–16`，`y 48–288` | |
| `Wall2` 右墙 | `x 416–432`，`y 48–288` | |
| `Wall3` 底墙 | `y 288–304` 全宽 | **连门洞一起挡**：门是"按 E 出去"，不是"走出去" |

底墙如果只在门洞两侧留缺口，玩家会顺着门洞走进房间外那 3 排装饰墙（同样没有碰撞）。实机复测：角色被限制在 `x ≈ 21–411`、`y ≈ 57–287`，四角会被正确夹住。

### 家具碰撞

床、床头柜、衣柜、壁炉、书柜、餐桌、冰箱、橱柜、厨房桌、摇椅、茶几、扶手椅在生成时都会带一个 `StaticBody2D`（碰撞矩形从脚底往上长）。所以玩家**不能穿过床**，只能绕到床脚——这也是"必须站在床边才能睡"的物理前提。地毯、椅子、盆栽、门垫、挂钟不挡路。

### 进出流程（带过渡）

| 环节 | 实现 |
| --- | --- |
| 门口 | `Farm/World/CottageDoor`（`house_door.gd`，mode=enter），按 E 触发 |
| 过渡 | 开门音 `door`（0.26s 木头吱呀，`build_sfx.gd` 合成）→ 渐黑 0.22s → 换世界 → 停 0.06s → 渐亮 0.30s |
| 进屋 | `HouseManager.enter_house()`：记下门外坐标 → 实例化室内（只建一次）→ 农场隐藏 → 玩家搬到 `Spawn` → 相机边界换成房间 |
| 出门 | 室内 `ExitDoor`（mode=exit）：反向操作，玩家回到门外坐标 + 12px |
| 过渡期间 | 锁玩家输入（`set_input_locked`），避免"黑屏里还能走动"；`player_in_range()` 在过渡中返回 false，防止连点 |
| 门贴图 | 室内门洞放 `door.png`，与触发点重合 |
| 相机 | `camera_follow.gd` 的 `set_world_bounds()`：换边界后重算最小缩放并 `reset_smoothing()`，避免从农场一路滑过来 |

黑幕由 `scripts/ui/screen_fade.gd` 提供：一个 `CanvasLayer`（layer 128，盖住 HUD 与面板）、一个可 tween 的 `ColorRect`、一句居中说明文字。`ScreenFade` 节点挂在 `Main` 下，脚本通过 `screen_fade` 组拿到它。

### 睡觉：进门 → 上床 → 天亮

睡觉点从屋外搬到了**室内床脚的 `BedSpot`**（`sleep_spot.gd`，半径 30）。完整流程按常见农场游戏的做法：

| 阶段 | 发生什么 |
| --- | --- |
| 1. 贴着床按 E | 只有距床 24px 内才能触发（`BedSpot` 半径 24，走开就睡不了）；弹出结算面板并锁输入 |
| 2. 点按钮 | 播放 `sleep` 音效 → 面板关闭 → **渐黑 0.45s** |
| 3. 黑屏里 | `HouseManager.begin_sleep()` 把角色挪到床上并 `visible = false`（"钻进被子"） |
| 4. 时间推进 | 见下方「白天小睡 / 晚上过夜」两条分支 |
| 5. 停留 0.9s | 让玩家读完文案，黑屏不闪 |
| 6. 醒来 | `finish_sleep()` 把角色放到 `WakeSpot`（床边）并显形，`fade_in 0.5s`，解锁输入 |

#### 白天小睡 / 晚上过夜

`TimeSystem.rest()` 按当前时间决定走哪条路，返回 `true` 表示跨天了：

| 当前时间 | 行为 | 日期 | 作物 | 存档 | 文案 |
| --- | --- | --- | --- | --- | --- |
| 06:00 – 17:59 | **小睡**：`nap()` 直接跳到 **20:00 同一天** | 不变 | 不结算 | 不存档 | 「小睡一会儿」→「醒来 · 第 N 天 20:00」 |
| 18:00 – 26:00 | **过夜**：`sleep()` 进入下一天 06:00 | +1 | 浇水过的长一阶 | 自动存档 | 「晚安 · 第 N 天」→「第 N+1 天 · 早上好」 |

- 阈值常量：`EVENING_MINUTES = 18:00`、`NAP_MINUTES = 20:00`
- 结算面板会跟着换文案：白天按钮是「小睡到 20:00」，标题写「第 N 天 · HH:MM 还没到晚上」；晚上按钮是「睡觉 · 进入第 N+1 天」
- 02:00 走的是星露谷式「累倒」分支：不弹面板，自动黑屏 → 扣 10% 金币（上限 1000）→ 进下一天 → 体力只回 50%；在屋里累倒从床边醒来，在室外累倒被送回农舍门口

> 早期版本是"点一下立刻跳天、角色还站在原地"，看起来像卡了一下；后来补了黑屏、文案和"躺下—起床"位移。现在又按你的要求区分了白天与晚上——白天上床不再白白浪费一整天。

### 存档边界

人可能在屋里存档或睡觉自动存档。`SaveSystem` 改为优先取 `HouseManager.save_position()`：在屋里时返回**门外坐标**，否则读档会落在室内那套偏移坐标上。

**验证**：`tools/check/check_house.gd` 共 53 项断言——黑幕节点存在、门口过渡后农场隐藏/室内可见/玩家换父节点/落在 Spawn/输入解锁/黑幕已清、床有碰撞体、`BedSpot` 与 `WakeSpot` 存在、**走开就睡不了**、白天按钮是「小睡」且日期不变、时间落在 20:00、晚上按钮是「睡觉」且日期 +1、时间回到 06:00、角色显形并落在 `WakeSpot`、黑幕清空、存档坐标仍在农场侧、出门复原。`-- --preview` 会把室内截图写到 `docs/screenshots/house-interior.png`。

### 鸡

`scenes/world/chicken.tscn` + `scripts/world/chicken.gd`：

```
Chicken (CharacterBody2D, motion_mode = FLOATING)
├─ Sprite (Sprite2D, hframes=4, vframes=2, offset(0,-7))
└─ Body (CollisionShape2D, 8×6, position(0,-3))
```

- 用 `CharacterBody2D + move_and_slide`：鸡自己绕开树、窝、房子，不需要寻路
- 游走范围以**出生点**为圆心，`home_radius = 40`，纵向按 0.6 压缩
- 到点后停 0.8–2.4 秒（`randf_range`），再挑下一个点
- 撞到东西（`get_slide_collision_count() > 0`）立刻换目标，不会贴着障碍物抖
- 走路帧 0.24 秒切一次，速度 16 px/s，看起来像在踱步

鸡是 `CharacterBody2D`，与玩家不会互相阻挡 —— 玩家不会被鸡堵在门口。

### 鸡窝

`scenes/world/props/chicken_coop.tscn` + `scripts/world/chicken_coop.gd`：

- 视觉用 `egg_and_nest` 的「巢+蛋」帧，放大 2×（32×32），配一块 26×10 的静态碰撞
- 没有专门的鸡舍建筑贴图（`free_chicken_house.png` 已被农舍占用），先用鸡窝代替；等有正式鸡舍素材再换
- 放在 `Farm/World` 的 `(520,264)`，避开可开垦区（`Rect2i(16,5,14,10)`）和玩家出门的动线

### 下蛋规则

监听 `TimeSystem.day_started`（睡觉结算后触发）：

```
每天产蛋数 = min(鸡的数量, 3 - 地上的蛋)
```

- 地上最多留 3 颗，捡不完也不会铺满地图
- 落点从 5 个候选位（窝左右各两个 + 正前方）里随机挑，离已有蛋不足 10px 就换一个

### 捡蛋

## 订单与社区中心

前面几版把「种 → 收 → 卖」做通了，但第 3 天之后就没有新东西可追：钱多了也只能买同样的两种种子。这一版补两层目标感：

- **日订单**（短期）：今天交一批货，拿比直接卖更高的价
- **社区中心**（长期）：分三阶段上缴物资，每修好一段就解锁新种子

### 日订单

`scripts/systems/orders.gd`，挂在 `Main/Systems/Orders`（组 `orders`）。

**生成规则**：监听 `TimeSystem.day_started`，每次睡觉换一张。

```
订单池 = 物品表里 category == "crop" 且 unlock_stage <= 社区阶段 且 sell_price > 0
物品    = 池子里随机一种
数量    = 3–6
报酬    = 卖价 × 数量 × 1.7（取整）
```

所以胡萝卜（卖 25）会变成「5 个胡萝卜 · 212 金币」，比直接卖 125 划算，玩家有动力攒货交单。

**交付**：`deliver()` 检查背包、扣货、`Economy.earn(reward)`、标记 `done`，然后立刻存档。同一天不能再交第二遍，睡醒才有新单。

**入口**：木屋旁的麻袋（`scenes/world/props/order_bin.tscn`，`(440,168)`），靠近按 `E` 打开 `UI/OrderPanel`。

面板显示图标、名称、`已备 / 需求`、报酬；材料不够时按钮变灰显示「货物不够」，够了按 `E` 或点按钮交付。

### 社区中心

`scripts/systems/community_center.gd`，挂在 `Main/Systems/CommunityCenter`（组 `community`）。

阶段表写在脚本里（`STAGES`），不依赖素材：

| 阶段 | 名称 | 需求 | 奖励 | 解锁 |
| --- | --- | --- | --- | --- |
| 1 | 修补围栏 | 木材 15 + 纤维 10 | 300 金币 | 萝卜种子上架 |
| 2 | 翻新集市 | 胡萝卜 10 + 鸡蛋 5 | 500 金币 | 小麦种子上架 |
| 3 | 装点农场 | 小麦 8 + 石头 10 | 800 金币 | 农场招牌挂上了 |

- `can_donate()`：当前阶段每一项都够才能交
- `donate()`：扣材料 → 阶段 +1 → 发奖金 → 发信号 → 自动存档
- `unlocked_stage()`：给商店用的解锁阶段号
- `progress()`：把「需求 / 持有」整理成面板能直接渲染的行

**入口**：`scenes/world/props/community_building.tscn`，放在地图左下 `(120,416)` 的空地上（脚本扫过全图，这块不压水也不压道具）。建筑用 `buildings/facilities/community_center.png`（96×80），碰撞只覆盖墙体下半部分 92×34。

面板 `UI/CommunityPanel` 显示：第几阶段 · 名称、描述、每项需求的 `持有 / 需求`（够了绿色、不够红色）、奖励与解锁内容、上缴按钮。

### 作物解锁

`ItemData` 新增 `unlock_stage`：

```gdscript
@export var unlock_stage: int = 0   # 0 = 一开始就能买
```

商店买入列表在 `_rebuild()` 里过滤 `item.unlock_stage <= community.unlocked_stage()`，被挡下的不显示货行，而是在列表末尾加一行灰字「还有 N 种货没解锁 / 去社区中心看看」，给玩家一条明确的下一步。

### 新作物：萝卜与小麦

素材里本来就有这两种作物的 6 张图（sprout / young / growing / mature / harvest / seeds），之前一直没用。

| 作物 | 种子买价 | 收获卖价 | 解锁阶段 |
| --- | --- | --- | --- |
| 胡萝卜 | 8 | 25 | 0 |
| 番茄 | 12 | 40 | 0 |
| 白萝卜 | 16 | 50 | 1 |
| 小麦 | 26 | 80 | 2 |

播种怎么选？之前 `_seed_id()` 取背包里**第一个**种子，解锁第二种作物后就卡住了。现在改成：

- `FarmTiller` 记一个 `_selected_seed`，拿种子袋时按 `Q / E` 在「背包里还有库存的种子」之间轮换，并弹提示「种子：白萝卜」
- 手选的那种用完了，`_seed_id()` 自动退回背包里的第一种
- 其他工具时 `Q / E` 照旧切换工具

### 存档

`SaveSystem` 加了两个字段：

```json
"community": { "stage": 1 },
"orders": { "item": "carrot", "count": 4, "reward": 170, "done": false, "day": 3 }
```

读档顺序有讲究：**先恢复社区阶段，再恢复订单** —— 订单池按解锁阶段筛选，顺序反了会把已解锁作物的订单读成空。旧档没有这两个字段时走默认值（阶段 0、订单为空则重新生成一张）。

### 验收

```powershell
godot --headless --path . --script res://tools/check/check_goals.gd
```

`check_goals` 覆盖：

- 订单箱、社区中心建筑、两个面板都在主场景里
- 开局阶段 0、自动有一张订单（数量 ≥3、报酬 >0）
- 阶段 0 时商店只卖胡萝卜/番茄种子，萝卜/小麦种子被挡
- 上缴第一阶段：材料被扣、300 金币到账、萝卜种子上架、小麦仍然锁着
- 交付订单：货被收走、奖金到账、当天不能再交第二次
- 睡一觉后有新订单
- `community` / `orders` 存档往返一致
- 三个阶段依次上缴到「全部修好」，修完后不能再交

### 已知限制

1. 订单只有「交作物拿钱」一种，没有 NPC 指名的、限时的、多选的订单。
2. 社区中心是纯上缴，修完没有视觉变化（建筑贴图不变），只解锁商品。
3. 没有季节 / 天气，订单不会因为下雨涨价。
4. 一天只有一张订单，做完就空着了。

## 体力与天气

前几版里干活没有代价、每天都是晴天，玩家可以一口气把整块地翻完。这一版补上两个"每天要做的取舍"。

### 体力

`scripts/systems/stamina.gd`，挂在 `Main/Systems/Stamina`（组 `stamina`）。

- 上限 100，开局满，**睡觉回满**（监听 `day_started`）
- `spend(amount)`：不够时**不改数**并返回 false，调用方据此拦住这次操作
- `can_spend()` / `ratio()` / `changed` 信号，HUD 订阅它

每种活的消耗写在 `FarmTiller.STAMINA_COST`：

| 操作 | 消耗 |
| --- | --- |
| 锄地 | 4 |
| 浇水 | 2 |
| 播种 | 2 |
| 收获 | 2 |
| 用斧头砍树 | 8 |
| 用镐碎石 | 6 |

拦截分两层：

1. `can_use()` / `can_interact()` 先看体力够不够 —— 不够就不起手，避免挥了空动画
2. `_on_use_requested()` 真正动手时再扣一次，双保险

体力不够时顶部提示变成「体力不够 · 按 E 回屋睡觉」，玩家知道该去睡觉而不是以为按键坏了。

### 天气

`scripts/systems/weather.gd`，挂在 `Main/Systems/Weather`（组 `weather`）。

| 天气 | 权重 | 效果 |
| --- | --- | --- |
| 晴 | 50 | 无 |
| 阴 | 30 | 画面稍闷（`tint` 0.88 灰） |
| 雨 | 20 | **自动给所有作物浇水** + 画面偏蓝 |

**什么时候翻天气**：挂在 `time_changed` 上，只在"日期真的变了"时重掷。这个信号在 `day_started` **之前**发出，所以作物结算时读到的已经是今天的天气。

**雨天怎么算浇水**：不改玩家的浇水状态，而是在 `FarmTiller.begin_new_day()` 里：

```gdscript
if rainy and not crop.is_mature():
    crop.water()          # 雨天等于浇过
if crop.grow_if_watered():
    grown += 1
```

同时把所有已开垦格标记为湿（`_soil_state[cell] = rainy`），玩家第二天看到地是湿的，不用再浇一遍。提示也换成「下雨了 · 今天不用浇水」。

**画面**：`day_night_tint.gd` 把天气色**乘**在昼夜色上（雨天 0.72/0.78/0.92），夜晚下雨会同时暗且偏蓝。

**可锁定**：`weather.lock(&"sunny")` 会让它不再按天随机 —— 回归测试用它固定晴天，否则"没浇水就不长"这类断言会 20% 概率随机失败。

### HUD

- 时间条右侧多一个天气字（晴 / 阴 / 雨）

### 季节（2026-11-04 新增）

一季 28 天、一年 112 天，四季循环：春 → 夏 → 秋 → 冬。

**不新增存档字段**：季节完全由 `day` 推导，老存档读进来直接就有正确季节。

```gdscript
season_index() = ((day - 1) / 28) % 4
day_of_season() = ((day - 1) % 28) + 1
year()          = (day - 1) / 112 + 1
```

`sleep()` 跨过 28 天整数倍时发 `season_changed(season, year)`，其余系统可按需订阅。

| 环节 | 表现 |
| --- | --- |
| HUD 时钟 | `春 3日 06:00`（季节 + 本季第几天，比累计天数好读） |
| 世界色调 | `DayNightTint.SEASON_TINTS` 与昼夜、天气做乘法叠加：春中性、夏偏暖、秋偏橙、冬偏冷 |
| 作物种植 | `CropData.seasons` 为空表示四季可种；错季时 `can_use()` 返回 false，悬浮提示「番茄 只在 夏 种，现在是春季」 |

| --- | --- |

| 土豆 | 春 / 夏 |

#### 项目名为什么还是 `My_ai_Game`

`application/config/name` 同时决定 `user://` 的真实路径（`%APPDATA%/Godot/app_userdata/<name>`）。改名会让所有老存档直接失联，所以**项目名保持不变**，正式名称改在窗口标题上显示：

- `AppSettings.PRODUCT_TITLE = "Pixel Farm · 像素农场"`，用 `call_deferred` 延到首帧后 `DisplayServer.window_set_title()`（headless 跳过）。

  > 坑：直接在 `_ready()` 里设会被引擎盖掉——启动后引擎还会按项目名再刷一次标题，实测窗口仍是 `My_ai_Game (DEBUG)`；延后一帧才稳定显示 `Pixel Farm · 像素农场`。
- 导出产品名走 `export_presets.cfg` 的 `application/product_name`
- `application/config/version` 设为 `0.9.0`
