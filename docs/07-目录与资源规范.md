# 目录与资源规范

本规范记录2026年11月5日按用户要求完成的目录整理。目标是找得到当前资源、看得出制作资料与运行成品的边界、知道代码和工具应该放在哪里。目录迁移不改变玩法规则、节点路径、物品ID、存档分区和正式保存版本。

## 1 根目录职责

| 目录 | 存放内容 | 引擎与发布 |
| --- | --- | --- |
| [art](../art/README.md) | 原图/提示词、外部参考、素材预览 | `.gdignore` 且显式排除导出 |
| [assets](../assets/README.md) | 可加载的贴图、完整素材批次、UI、音频、TileSet、Shader | 运行资源 |
| [scripts](../scripts/README.md) | 按业务模块分类的运行代码 | 运行资源 |
| `scenes/` | Godot 节点树、场景和 SpriteFrames | 运行资源 |
| `data/` | 物品、作物、配方、动物、地图等 Resource 实例配置 | 运行资源 |
| [tools](../tools/README.md) | 切片、预览、场景构建、隔离回归、目录维护 | 仅开发，排除导出 |
| `docs/` | 当前规划、架构、系统设计、素材记录和验证证据 | 排除导出 |
| [archive](../archive/README.md) | 旧工具和旧说明，仅留追溯 | `.gdignore` 且显式排除导出 |
| `build/` | 导出包、运行截图、日志和一次性诊断结果 | `.gdignore`、排除导出且不入库 |
| `addons/` | 第三方编辑器插件 | 不在这里放业务代码，保持原插件只读 |

根目录只保留工程配置、项目说明与上述职责目录。统一命名 `assets/`，不新建 `asset/`、`generated/` 等平行资源根目录。

## 2 美术的制作与接入

```text
art/sources/<批次>/ 原图、完整提示词
          ↓ tools/art/prepare_*.gd 技术整理
assets/textures/<用途>/ 或 assets/packs/<批次>/ 成品、图集、catalog
          ↓ data/*.tres、scenes/*.tscn 或运行表现装配
游戏画面
          ↓ tools/preview/preview_*.gd
art/previews/<批次>/ 素材总览；build/ 游戏实景截图
```

独立的基础贴图按 characters、buildings、crops、items、terrain、trees 分类。包含清单、动画和图集的整套生成批次保留在 `assets/packs/`，不把同一批次文件打散成难以还原来源的零散图片。目录版本用于溯源，当前采用哪张图以实际 Resource/场景引用为准，查找优先级见 `assets/README.md`。

当前建筑、家具、头像和设备状态优先查看 `presentation_v3`；当前部分作物与野浆果查看 `farm_style_v2`；区域地表与资源查看 `world_regions_v1`；鱼、渔具和后续动物查看 `expansion_v1`；更多全品类资源查看 `content_v1`。这些目录均有分类子目录或 catalog，不将资源齐全等同于玩法已完成。

原图不覆盖；预览不能作为游戏精灵加载；外部参考仅核对内容清单。PNG 保持像素规格和最近邻，文本资源使用 UTF-8 无 BOM。Godot 的 `.import`、脚本 `.gd.uid` 是资源配套文件，移动时保留；`.godot/` 由引擎重建，不直接编辑或提交。

## 3 代码与数据

组合根仍是 `scripts/core/game_session.gd`。金币/交易、库存、日期天气、任务成长、活动、保存、界面、表现和场景适配分别进入其业务目录，具体定位表见 `scripts/README.md`。

`world/` 下分 farming、resources、interiors、interactions、navigation、maps，避免再把整个世界脚本堆在一个目录；动物进入 `animals/`，纯表现进入 `presentation/`。`ui/` 下分 common、panels、menus、hud、presenters；Presenter整理显示数据与转交操作意图，模型和应用服务继续放所属业务模块，不新增全局models/views/controllers平行目录。区域整合的独立服务沿用 `regions/`，不与目录迁移混做业务重构。

自定义 Resource 类在 `scripts/data/`，其配置实例在根目录 `data/`。目录变化不改 `class_name`、组名、节点身份、物品ID或保存分区，不为了文件归类建立第二套库存/时间/交易数据。依赖方向继续遵守 [架构规范](06-架构与开发规范.md)。

## 4 工具唯一入口

| 工作 | 入口 |
| --- | --- |
| 启动游戏 | `pwsh -NoProfile -File tools/run_game.ps1` |
| 全量/指定回归 | `pwsh -NoProfile -File tools/run_checks.ps1 [-Suites ...]` |
| 整理已有生成图 | `godot --headless --path . --script res://tools/art/prepare_*.gd`，替换成具体文件名 |
| 渲染素材或游戏画面 | `godot --path . --script res://tools/preview/preview_*.gd`，替换成具体文件名 |
| 重建场景、音频与动画 | `tools/build/` 中对应脚本；会覆写目标资源，运行前确认范围 |
| 目录及路径检查 | `python tools/maintenance/audit_project_layout.py` |
| 工具共享类 | `tools/lib/`，由其他工具调用，不单独运行 |

原来 tools 根目录的三份旧 GDScript 在 `archive/tools/`。所有命令指向正式 build/check 版本，归档不作为备用执行入口。回归脚本仍受隔离保护；测试入口复制 `art/` 是为了读取原始 PNG 验证来源，不代表这些资料进入游戏或发行包。

## 5 常用旧路径对照

| 旧位置 | 现在的位置 |
| --- | --- |
| `assets/generated/sources/<独立批次>/` | `art/sources/<批次>/` |
| `assets/generated/sources/` 中早期散装大图 | `art/sources/base/` |
| 根目录 `星露谷物语素材/` | `art/reference/stardew_valley/` |
| `assets/game/` | `assets/textures/base/` |
| `assets/generated/characters,crops,items,terrain,trees,buildings,field` | `assets/textures/` 对应分类 |
| `assets/generated/content_v1,expansion_v1,farm_style_v2,presentation_v3,world_regions_v1` | `assets/packs/` 对应批次 |
| `assets/generated/ui/` | `assets/ui/` |
| 原成品目录中的 preview/previews 图 | `art/previews/` 对应类别/批次 |
| `tools/art/preview_*.gd` | `tools/preview/preview_*.gd` |
| `tools/art/held_tool_painter.gd` | `tools/lib/held_tool_painter.gd` |
| `scripts/systems/save_system.gd` | `scripts/persistence/save_system.gd` |
| `scripts/systems/inventory.gd`、`stack_store.gd` | `scripts/inventory/` |
| `scripts/systems/economy.gd`、`trade_service.gd` | `scripts/economy/` |
| `scripts/systems/time_system.gd`、`weather.gd` | `scripts/time/` |
| 原 settings/audio 服务 | `scripts/platform/` |
| 原任务、订单、引导、好感与升级服务 | `scripts/progression/` |
| 原相机、遮挡、昼夜、工具特效等 world 脚本 | `scripts/presentation/` |
| 原 world 中的鸡、鸡舍和蛋 | `scripts/animals/` |
| 原 UI 根目录脚本 | `scripts/ui/common,panels,menus,hud/` 对应职责 |

精确的旧路径字符串映射保存在 `tools/maintenance/path_migrations.json`。维护工具默认只读；需要接纳仍引用旧位置的并行修改时，显式追加 `--repair-legacy-paths`，只修复已知路径，不重复移动或删除文件。
