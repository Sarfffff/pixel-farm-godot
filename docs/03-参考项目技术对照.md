# 参考项目技术对照：KimiLook（Unity《麦田物语》）

参考仓库：https://github.com/yuyucode/KimiLook （MIT，35 stars）
性质：Unity + C# 的 2D 农场模拟经营**教学工程 + 中文笔记**，源自 Unity 中国官方课程《麦田物语》（MFarm）。不是成品游戏，价值在于"2D 农场关键子系统的实现速查表"。

本文只做一件事：把它验证过的做法，翻译成本项目（Godot 4.7）的等价方案，并指出哪些能抄、哪些不能抄、哪些它没做而我们更需要。

---

## 一、它覆盖了什么（与我们的版本路线对照）

| 它的模块 | 本项目对应版本 | 可复用程度 |
| --- | --- | --- |
| Pixel Perfect Camera + Cinemachine 跟随/边界 | V0.2 玩家与镜头 | 高（概念完全一致） |
| Transparency Sort Mode = Custom Axis(0,1,0) + Pivot 在脚底 | V0.3 遮挡排序 | 高 |
| Tilemap / Tile Palette / Rule Tile / Sprite Atlas 去缝 | V0.1 地图 | 高 |
| Tilemap Collider + Composite Collider + Custom Physics Shape | V0.3 碰撞 | 高 |
| ScriptableObject 物品表（`ItemDataList_SO`） | V0.6 商店/物品 | 高 |
| 静态事件总线 `EventHandler` + 单例 `InventoryManager` | V0.6 背包 | 中（Godot 用信号） |
| 背包 UI 事件刷新、拖拽（`IDropHandler`） | V0.6 / V1.0 | 中 |
| Animator Blend Tree + Override Controller 换装 | V0.2 / V1.0 | 中（Godot 用 SpriteFrames） |
| DOTween 补间 | V1.0 反馈打磨 | 中（Godot 内置 Tween） |
| 存档、时间/日历、作物生长、经济、动物 | 无（课程没做） | 无，需自行设计（见 `02` 文档 V0.5–V0.8） |

**关键判断**：它强在"引擎技巧 + UI 数据流"，弱在"进度的长线系统"。而农场游戏的核心恰恰是后者。所以它只能当**技术参考**，不能当**设计参考**。

## 二、技术方案逐项对照（Unity → Godot 4）

### 1. 像素完美与分辨率

| 它 | 我们 | 落地要点 |
| --- | --- | --- |
| Pixel Perfect Camera（Assets Pixels Per Unit = 16，Reference Resolution） | 基准视口 320×180 + `stretch/mode=canvas_items` | 已有 `canvas_items`，需补 `display/window/size/viewport_width=320`、`viewport_height=180` |
| Filter Mode = Point | `rendering/textures/canvas_textures/default_texture_filter = 0`（Nearest） | **当前缺失，必改**，否则整套像素画发糊 |
| Ortho Size 9 | 正交相机，缩放由视口决定，不再手动调 | 320×180 已把 16px 瓦片放大到合适大小，不需要额外 zoom |

> 注意：不要在 Godot 里再把 Camera2D 的 `zoom` 设成 2、3 这种值，会和窗口拉伸打架。缩放交给窗口拉伸，相机只负责位置。

### 2. 摄像机跟随与边界

| 它 | 我们 |
| --- | --- |
| Cinemachine Virtual Camera + Body 阻尼 + Confiner2D 限位，`SwitchBounds` 换边界 | `Camera2D` 的 `position_smoothing_enabled` + `limit_left/right/top/bottom` |

落地要点：
- 相机挂在玩家下会跟着动画抖动，**相机应作为独立节点，在 `_physics_process` 里跟随玩家的脚底位置**。
- `limit_*` 用地图像素边界填死（40×30 格 = 0..640 / 0..480），场景切换时更新这四个值。这就是它的 `SwitchBounds` 的等价物，不需要额外脚本。
- 平滑系数从 `8.0` 起调（`position_smoothing_speed`），过高会跟不动，过低会飘。

### 3. Y 轴遮挡排序（最容易踩坑的一项）

| 它 | 我们 |
| --- | --- |
| Project Settings → Graphics → Transparency Sort Mode = Custom Axis，Axis = (0,1,0) | `CanvasItem.y_sort_enabled` + `y_sort_origin` |
| Sprite Sort Point = Pivot，Pivot 设在脚底 | `Sprite2D.offset` 让贴图以脚底为原点；`y_sort_origin` 设为 0（脚底） |
| Sorting Group 让父子整体排序 | 父节点 `y_sort_enabled = true`，子节点不单独破排序 |

落地要点：
- 排序容器的父节点（如"物件层" `Node2D`）开启 `y_sort_enabled`，其所有子节点按**自身 y 坐标**排序。
- 精灵的锚点必须是脚底中心，否则会出现"人物半截插进屋顶"。
- `TileMapLayer` 同样支持 `y_sort_enabled`，但地形层不要开，只有物件层开。
- 树之类的"底部小、上方大"的物件，其 y 坐标用树根位置，不是图片中心。

### 4. Tilemap 与瓦片缝隙

| 它 | 我们 |
| --- | --- |
| Tile Palette 绘制；Rule Tile 自动连边；Random Brush 随机变体 | `TileSet` 的 **Terrain Sets（地形集）** 做自动过渡；`TileMapLayer` 绘制 |
| Sprite Atlas：Filter = Point、Compression = None、**加大 Padding** 解决瓦片间缝隙 | 单张 PNG 直接做图集，关键在**过滤设 Nearest + 不做压缩 + 关闭 mipmap**；如打图集则必须留 2px padding |
| Tilemap Collider 2D + Composite Collider 2D（Used By Composite） | `TileMapLayer` 设置 `physics_layers` + 图块 `physics` 多边形；碰撞合并由 TileSet 物理层自动处理 |

落地要点：
- 我们的 `grass.png`(176×112)、`tilled_dirt*.png`(176×112) 是 11×7 格，属于"3×3 极简 + 变体"布局，用 Terrain Sets 的 3×3 模式即可，不必强上 47 位全掩码。
- `bitmask_references_1/2.png` 是**参考图**（说明素材对应的掩码组合），不是当瓦片用的图，别拖进 TileSet。
- 草地与耕地的交界要"耕地叠在草地之上"，用两个 `TileMapLayer`：地面层（草地/水/路）+ 覆盖层（耕地），避免互相覆盖冲突。
- 瓦片边缘出现 1px 缝隙时，优先查：过滤是否为 Nearest、是否有 mipmap、图集是否留 padding，**不要**去改图块尺寸。

### 5. 数据驱动（ScriptableObject → Resource）

| 它 | 我们 |
| --- | --- |
| `[CreateAssetMenu]` 生成 `ItemDataList_SO`，Inspector 编辑物品表 | `class_name CropData extends Resource` + `@export` 字段 + `.tres` 文件 |
| `ItemDetails` / `InventoryItem` 结构体 | 自定义 `Resource` 或 `RefCounted` 数据类 |

落地要点：
- 用 Godot 4 的 `@export` 暴露字段，字段上写 `@export_group` 分组，Inspector 体验接近 SO。
- 资源文件放 `data/`（`data/crops/`、`data/items/`），路径固定，代码只 `preload` 目录式清单或按 id 查表。
- **它这里有个已知缺陷**：`AddItem` 中"背包无该物品且无空位"的分支未处理（作者自标 TODO）。我们的对应做法是 `inventory.add_item(id, count) -> int` **返回实际存入数量**，永不静默丢弃。

### 6. 事件驱动 + 单例 → 信号 + Autoload

| 它 | 我们 |
| --- | --- |
| `public static event Action<...> OnUpdateInventoryUI` + `EventHandler.Call...` 广播 | Autoload `EventBus`（`Node`）里的 `signal inventory_changed(slots)`，或直接 `InventorySystem.inventory_changed` |
| `Singleton<InventoryManager>` 管理器 | Autoload（`GameState`、`InventorySystem`、`TimeSystem`、`SaveSystem`） |
| UI 在 `OnEnable` 订阅、`OnDisable` 退订 | `_ready` / `_enter_tree` 里 `connect`，`_exit_tree` 里 `disconnect`（或用 `CONNECT_ONE_SHOT`） |

落地要点：
- Godot 信号天然解耦，不需要自造静态事件总线类；但**跨系统通信集中在一处**的思路要保留：`EventBus` 只放"全局广播"（`day_changed`、`item_obtained`、`gold_changed`），系统内部事件用各自信号。
- **它的另一个隐患**：静态事件订阅忘记退订会导致重复刷新甚至空引用。Godot 里同样存在（节点释放后信号仍连到旧回调）。规则：跨节点连接一律在 `_exit_tree` 断开，或 `connect` 时传 `CONNECT_ONE_SHOT`/使用 `is_instance_valid` 防护。
- 单例不要做成"上帝对象"。它在 `InventoryManager` 里同时管数据、查容量、改数据、通知 UI，我们拆成：`InventorySystem`（数据）+ `inventory_bar.tscn`（只订阅刷新）。

### 7. 动画

| 它 | 我们 |
| --- | --- |
| Animator：`idle` Blend Tree + `Walk Run`，`isMoving` 参数 | `AnimatedSprite2D` + `SpriteFrames`，或 `AnimationTree`（`StateMachine`） |
| Animator Override Controller 派生 Body/Hair/Arm 复用状态机 | 复用 `SpriteFrames`：同一套动画名 + 不同图集，换 `sprite_frames` 即可 |

落地要点：
- 我们只有一整套角色素材，V0.2 先用 `AnimatedSprite2D` + 动画名 `idle_down/walk_down/...` 十六个动画，够用。
- 真的有换装需求（V1.0 之后）再上 `AnimationTree`，别提前上。
- 走路动画播放速度与移动速度挂钩（`speed_scale`），否则慢走时脚底打滑。

### 8. UI（UGUI 事件接口 → Control）

| 它 | 我们 |
| --- | --- |
| `IPointerClickHandler` 等一堆接口 | `Control` 的 `gui_input` / 内置 `pressed` 信号 |
| `IBeginDragHandler` / `IDragHandler` / `IDropHandler` | `_get_drag_data()` / `_can_drop_data()` / `_drop_data()` |
| 拖拽图片必须取消 `Raycast Target` | 拖拽预览用 `Control.mouse_filter = MOUSE_FILTER_IGNORE` |
| `LayoutRebuilder.ForceRebuildLayoutImmediate` 解决多列文本延迟 | `await get_tree().process_frame` 后读取尺寸；或 `Container.queue_sort()` |

落地要点：
- 背包格用 `Panel` + `TextureRect` + `Label`，格子里所有子节点设 `mouse_filter = IGNORE`，让点击落到格子上——和它"关掉 Raycast Target"是同一个坑。
- Godot 的 `_drop_data` 只会在 `_can_drop_data` 返回 `true` 时触发，判定条件要写全（格子可放、物品可堆叠、数量够）。

### 9. 补间与反馈

| 它 | 我们 |
| --- | --- |
| DOTween（第三方） | 内置 `create_tween()`，无需插件 |

落地要点：金币飘字、收获弹跳、面板滑入全部用 `Tween`，不要手写 `_process` 插值；`Tween.kill()` 在节点释放前确保停止（或用 `tween.bind_node(self)` 自动处理）。

## 三、可以直接照搬的"做法"（与引擎无关）

1. **Pivot/锚点必须在脚底**——这是 Y 遮挡排序成立的前提，不是可选项。
2. **导入参数用统一预设**，不逐个手调。对应 Godot：`.import` 参数统一（过滤 Nearest、压缩关闭、mipmap 关闭），靠一次配置 + 复用。
3. **数据表与逻辑分离**：物品、作物、商品全部配置化，加内容不改代码。
4. **UI 通过事件刷新，不直接改数据**：UI 只订阅、只发请求。
5. **编辑器工具放在独立目录**：它用 `Assets/Editor`（不打包）；我们用 `addons/`（第三方）与 `tools/`（自研编辑脚本），业务代码不进 `addons/`。
6. **目录按职责分**：`Scenes / Scripts / Prefabs` → 我们的 `scenes / scripts / assets / data`。
7. **组件依赖显式声明**：它用 `[RequireComponent]`；Godot 用 `@onready` 强类型引用 + `assert` 校验，缺节点时早失败。

## 四、它踩过的坑（我们要提前避开）

| 它的问题 | 我们的对策 |
| --- | --- |
| `AddItem` 背包满时无处理（TODO） | `add_item()` 返回实际存入数，UI 提示"背包已满" |
| 静态事件订阅未退订 | 跨节点信号在 `_exit_tree` 断开；Autoload 信号只在 Autoload 内发 |
| 事件/单例职责过载（`InventoryManager` 什么都干） | 数据、规则、表现三层分开；Autoload 只放状态与广播 |
| 瓦片缝隙靠改图解决 | 先查过滤/压缩/padding 三件事，图不动 |
| 拖拽 UI 被自身图片挡住判定 | 子节点 `mouse_filter = IGNORE` |
| 学习工程无存档（进度一关就没） | 我们把存档提到 V0.7，且**格式带版本号**（这是它完全没有的部分） |

**许可证提醒**：仓库是 MIT，笔记与代码可参考；但 `Assets/` 里的美术可能来自课程/第三方，**不要直接取用其中图片或音频**。本项目继续使用现有 `assets/textures/base/`（Sprout Lands 风格素材），并在 `CREDITS.md` 记录来源。

## 六、结论

- **可以学**：它的摄像机边界、Y 轴排序、Tilemap 去缝、ScriptableObject 配置化、事件驱动 UI 刷新，这五点直接对应我们 V0.1–V0.6 的关键实现，能少踩很多坑。
- **不要学**：单例什么都管、事件不设生命周期、背包满不处理、无存档设计——这些是教学工程的通病，农业模拟游戏会在第 7 天之后集中爆发。
- **它的空白正是我们的重点**：时间/日历、作物阶段、经济曲线、存档兼容、长线目标。这四块在 `02-可玩版本演进路线图.md` 的 V0.5–V0.8 里已经排好。
